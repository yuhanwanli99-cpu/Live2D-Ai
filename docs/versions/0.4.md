## 主仓行为

1. 缺省工厂 0 的树能对 `x86_64-pc-windows-msvc` 做 `cargo check -p live2d-ai-desktop`。Unix 专用调用保持 `cfg`。机器上没有 Windows SDK 或交叉工具时，交付写明工具链没装。Linux 编译通过不能代替这一条。
2. 资源查找增加 exe 所在目录：`web/`、`assets/models`、`assets/actions`。现有仓库根查找保留。`scripts/ignite.sh` 不改。
3. `mods/` 扫描保留 cwd。再看 exe 目录下的 `mods/`。同一 id 以 cwd 为准。保留 id 仍不可选：`director`、`local-llm`、`wallpaper`、`pet-desktop`、`local-tts`。
4. 只有 Windows 目标在监听成功后打开默认浏览器，地址是启动器页。用系统 `cmd /C start`，不新增依赖。Linux 仍由 `ignite.sh` 打开，服务自己不再开一次。
5. 文件夹子进程仍不加参数、不经 shell、不传 `.env`。入口必须是 exe 文件本身，`.sh` / `.bat` 不起。环境在 `PATH`、`HOME`、`LANG`、`LC_ALL` 之外，Windows 上再带上已存在的 `SYSTEMROOT`、`USERPROFILE`、`PATHEXT`。父进程退出时结束自己记下的子进程。
6. 设置保存后的自重启继续用 `current_exe`。不要改成去叫 WSL。
7. 缺省 `--web` 仍不打开服务端声卡。包脚本不设 `LIVE2D_AI_WEB_AUDIO=server`。

路径、扫描锚点和环境名单做成纯函数，在 Linux 上测试。

### 两条纯函数

新文件 `crates/l2d/src/asset/lip_sync.rs`，本文件 ≤500 行。`asset/mod.rs` 在 `mod manifest;` 旁加 `mod lip_sync;`。

1. `lip_sync_ids(json: &serde_json::Value) -> Vec<String>`
   - 只看 `Groups` 数组。没有这个键、或不是数组，返回空。
   - 只收 `Target == "Parameter"` 且 `Name == "LipSync"` 的项。两个比较都精确、区分大小写。`lipsync`、`LIPSYNC`、`EyeBlink` 都忽略。
   - `Ids` 里的字符串按出现顺序留下。非字符串跳过。`Ids` 缺失或空则这一组不贡献 id。
   - 有多条符合的组时，按出现顺序接成一条。
   - 这个函数内部不准补 `ParamMouthOpenY`。

2. `mouth_write_ids(lip_sync: &[String], has_param_mouth_open_y: bool) -> Vec<String>`
   - `lip_sync` 非空：原样返回这一份。不要再追加 `ParamMouthOpenY`。组里某个 id 在模型上不存在也留着，`set_parameter` 对缺 id 是空操作。
   - `lip_sync` 空、且 `has_param_mouth_open_y` 为真：返回 `vec!["ParamMouthOpenY"]`。这是 bai 和 Mark。
   - 两者都没有：返回空。这是 Rice。不要发明别的嘴 id。

`has_param_mouth_open_y` 用 `loaded.handle().has_parameter("ParamMouthOpenY")`，只在装载时查一次。不要扫 cdi3，不要每帧查。

### 缺陷 2：日志目录跟着 cwd，建文件失败会 panic

`crates/live2d-ai-desktop/src/logging.rs` 现为 450 行。`default_log_dir`（约 123 行）在没有 `XDG_DATA_HOME`、也没有 `HOME` 时返回相对路径 `logs`。Windows 双击常常没有 `HOME`（有的是 `USERPROFILE`），于是日志落在当前目录。`init_logging` 调用 `tracing_appender::rolling::daily`。0.2.5 的 `rolling.rs` 第 156 行 `.expect("initializing rolling file appender failed")`，目录存在但写不了文件时直接 panic。`main.rs` 约 139 行本来会接 `Err` 并打印「日志系统初始化失败（已降级仅 stdout）」，panic 走不到那里。`Start-Process -WorkingDirectory C:\Windows` 就是这条：`InitError { context: "failed to create log file", code: 5 }`。exe 目录可写时，第一次双击能在 exe 旁建出 `logs/`，那条不是失败。

`host_layout.rs` 现为 449 行。`is_wsl_network_path`、`exe_dir` 已经能用。两个旧文件都不得超过 500。路径选择放新文件。`logging.rs` 里只把 `daily(&dir, "live2d-ai.log")` 换成等价的、会返回 `Result` 的写法：

```rust
RollingFileAppender::builder()
    .rotation(Rotation::DAILY)
    .filename_prefix("live2d-ai.log")
    .build(&dir)
```

不要加 `filename_suffix("log")`，否则文件名从 `live2d-ai.log.YYYY-MM-DD` 变成另一种。`Err` 映射成现有的字符串错误，让 `main.rs` 的 stdout 降级生效。

路径（纯函数，测试注入 exe 与环境，不要读进程真实环境）：

- 有 `XDG_DATA_HOME`：仍是 `$XDG_DATA_HOME/live2d-ai/logs`。
- 否则有 `HOME`：仍是 `$HOME/.local/share/live2d-ai/logs`。
- 否则 exe 不是 WSL 网络路径：`<exe_dir>/logs`。例：exe 为 `C:\pack\live2d-ai-desktop.exe` → `C:\pack\logs`。
- 否则：`%LOCALAPPDATA%\live2d-ai\logs`。
- 永远不要返回相对的 `logs`。

Linux 回归：对一个已存在但不可写的目录，`init_logging` 返回 `Err`，不 panic。`create_dir_all` 对已存在目录会成功，所以这条要打到 `build` 的 `Err`，不要只测「目录创建失败」。有 `HOME` 的现有测试 `default_log_dir_ends_with_live2d_ai_logs` 保持通过。

### 未验

- **Windows 运行时全部未验**：MessageBox 弹窗与静默判据、APPDATA 落点、`WM_CLOSE` / `CTRL_BREAK_EVENT` 是否被 Mod 响应、Job 挂起恢复、`%TEMP%` 实际落点、`0xC0000135` 在真实 `CreateProcess` 失败时的取值。等 Windows 真机（或 CI msvc 包）验收；不拿 Linux 单测冒充。
