# 0.7 线：companion 收口（v0.7.0-rc.1）

> 状态：**活** · 立档 2026-11-19 · 覆盖 0.7.0-rc.1。
> 这一篇是 0.7 大版本文档，单独计行数（**不进** docs 合计 45,000 的那条预算）。
> 代码真源仍是源码与 `docs/architecture/CURRENT.md`；本文记录**范围、契约裁决、迁移与验收边界**。

## 1. 为什么有 0.7 线

0.6.0 把 Windows 原生 CosyVoice3 TTS 收口了；`pet/companion` 线上又长出了桌宠、热槽记忆、
会话 UX 20 条与语音分档，但项目审查（2026-11-19）判定它**还不是可重复发布的正式版**：

- 产品契约三处直接冲突（打包 Mod 数、出厂人设、stop 语义）；
- 配置保存可能覆盖损坏或读取失败的原文件；
- Mod 生命周期与订阅权限未闭合（子进程泄漏 / 已停用 Mod 仍收事件）；
- TTS 故障表现为「成功但静音」；
- 发布链绿灯 ≠ 产品可运行（发布单元不含 Flutter / Trunk / assets）。

0.7 线**不扩功能**，只做收口：可重复发布、不串会话、不丢配置、语音状态诚实。
新平台 / 新供应商 / 新 Mod / 动态加载器一律不进 0.7。

## 2. 产品契约（0.7.0 定稿）

### 2.1 出厂不设人设（2026-11-19 裁决）

- `[persona].system_prompt` **出厂为空就是空**：不再像 2026-11-16 M2 那样用一句固定陪伴句
  兜底；空串不会产生 system 消息（热槽记忆的「钉住的事 / 热卡 / 摘要」仍由 host 另拼）。
- 用户自己写的非空句子原样使用，不拼接、不覆盖。
- 与 `origin/main` 的「出厂不设人设」口径一致；撤销 M2 只影响**未发布的 companion 分支**，
  0.6.0 正式包用户无感。
- 角色卡 Mod（persona）不挂回；耐久事实在「钉住的事」里。

### 2.2 打包 Mod = 6 个（2026-11-19 裁决）

`external-input` / `local-tts` / `local-engine` / `a2a` / `cosyvoice3-tts` / `desk-pet`。
**不是** `origin/main` 的 8 个的超集，也不是 9 个的折中。

legacy 三仓 **`persona` / `memory` / `voice-input`** 的去向：

- 不再随包、不再挂回宿主（代码留在公开仓库，保留历史与自建可能）；
- 维护级别 = **legacy**：只做安全与「能编译」的修复，不承诺兼容演进、不接新需求；
- 文档与仓库 README 需明示 legacy（仓库侧动作见 `REPO-AUDIT-mod-repos-2026-11-19`）。

### 2.3 stop / 切会话语义（2026-11-19 裁决）

- 切走会话时**尽力取消**当前生成；
- 迟到结果**只归档回它自己的会话**（不丢弃、不串到新会话）——这就是 #21 的落点；
- 旧轮**真正终止之前**，全局 single-flight 不释放（否则 B 会话能在 A 还在跑时叠一轮）。
- 验收口径以本条为准；旧的「迟到帧必须静默丢弃」验收项作废。

## 3. 0.7.0 变更

### 3.1 配置安全（P0）

- `AppSettings::to_toml_string_merging` 改为返回 `Result`：只有「文件不存在 / 确为空」才整份生成；
  其它读失败、非空文件解析失败一律**报错且零写盘**。
- PATCH 写盘失败映射为 HTTP 500 `persist_failed`；Mod `apply_settings` 路径返回 false 并留痕。
- 回归测试：坏 TOML 上点保存 → 原文件**逐字不变**；缺失文件仍能首写。

### 3.2 密钥路径唯一（P1）

- 启动时确定唯一 `.env` 路径：`LIVE2D_AI_ENV_FILE` > **配置文件同目录** `.env`；
  读取、写入、状态展示、file_watcher 全部共用同一路径。
- 修复「从非包目录启动时，配置从 exe 目录、密钥从 cwd、热重载又监听另一个目录」。

### 3.3 Mod 生命周期与订阅（P1）

- enable 幂等；重复 enable 先停旧实例；start 失败清槽位并置 `Failed`；disable 真正 teardown。
- `subscribe()` 记录 topic；事件只投给**订阅了该 topic** 的 Mod；unsubscribe 生效。
- 目标：不再有子进程泄漏 / Failed 与真实状态矛盾 / 对话向未订阅 Mod 扩散。

### 3.4 发布完整性（P0）

- `scripts/pack_windows_glue.py`：gnu release 失败 / rust-std 缺失**不再降级为 warn**；
  组装后终检 exe / web/app / web/render / assets / 配置模板，缺任一项非零退出。
- `--skip-cargo` / `--skip-trunk` / `--skip-flutter` 是唯一合法的「只拼一部分」入口。
- CI：Rust 固定 1.98.1、Flutter 固定 3.47.3；`flutter-checks` 增加 `push: main` 触发
  （此前直接 push main 的前端可以绕过门禁）。
- 正式 RC 包 = 本脚本产出的 zip；`release-build.yml` 的桌面二进制**不是**发布包（仍在改）。

### 3.5 门禁（0.7.0-rc.1 实测，2026-11-19）

- `cargo test --workspace --all-targets`：全绿（desktop 745 / runtime 368 / 集成齐全，0 failed）。
- `cargo test --workspace --doc`：3 passed。
- `cargo fmt --all -- --check`：通过。
- `cargo clippy --workspace --all-targets -- -D warnings`：通过（修复 rust 1.98 的 8 条新 lint）。
- `cargo run -p xtask -- code-stats --check`：PASS（docs 44,999 / 45,000；>500 行 22；deps 18）。
- Flutter：本轮零 Dart 改动，未重跑；RC 前必须重跑 `flutter analyze` + `flutter test`。

## 4. 迁移（0.6.0 → 0.7.0-rc.1）

- **配置格式不变**（`deny_unknown_fields` 仍然严格）；不需要手改 toml。
- 坏 TOML 行为变化：以前可能在保存时被整份重写，现在保存会被拒（500 `persist_failed`），
  原文件保留。用户需先修好 TOML 或删除文件再保存。
- `mods.json`：0.6.0 的 8 Mod 清单里 `persona` / `memory` / `voice-input` 在 0.7 不再编入；
  旧文件加载时必须给出**明确忽略/告警**，不能静默失败——RC 验收项。
- 密钥文件：从「双击 exe / 非包目录启动」时，`.env` 现在锚定**配置文件同目录**；
  想保留旧位置可显式设 `LIVE2D_AI_ENV_FILE`。
- 会话：存档 v2 与热槽记忆是 companion 线新能力，0.6.0 用户没有旧数据要迁。

## 5. 0.7.0-rc.1 出门条件（验收清单）

1. 全部门禁绿（Rust / Flutter / docs / 密钥扫描 / rust 占比）。
2. Windows 真机：zip 干净解压 → 首次启动 → 6 Mod 列表 → `/app/` 对话 → `/render` 换装 →
   端口释放 → 菜单六组副作用 → 设置保存/重载 → 会话切换与 stop 竞态。
3. `.env` 三种启动方式（包目录双击 / 从别处 cmd / 设环境变量）读到的密钥一致。
4. 坏配置零覆盖在真机上复现一次（截图 + 原文件 sha 不变）。
5. GitHub：6 个打包 Mod 仓库的 PINNED sha 均可达；`live2d-ai-mod-desk-pet` 建仓完成；
   legacy 三仓的 deprecation 状态落盘。
6. 语音桌宠（按住说话 / 常开监听）与长期记忆若未达证据要求，发布说明标 **beta**，不阻塞基础产品。
