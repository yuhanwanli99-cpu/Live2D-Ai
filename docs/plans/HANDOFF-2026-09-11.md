## 7. 几个必须知道的坑（都踩过）

- **`dart format` 会改 64 个文件**。这台机器的 Dart 3.13 用新版格式，与仓库现存风格不一致，
  跑一次 `dart format lib test` 会产生上千行无关 diff。**只在单个新文件上用**，别全树跑。
- **`pkill -f '<binary> --web'` 会杀掉自己**：同一条 `bash -c` 里既有 `pkill` 又有启动命令时，
  命令行里含有那个字符串，模式会匹配到自己。**把 pkill 与启动分成两次工具调用**。
- **`trunk build` 需要 `unset NO_COLOR`**（空的 `NO_COLOR` 会让它报 `--no-color` 缺值）。
- **`cargo test` 的 `cwd` 是 package 目录**，`wasm_dist_dir()` 因此依赖
  `../crates/l2d-wasm-demo/dist` 这一档回退；测试里别断言 `/render` 回 200。
- **`showModalBottomSheet` 的 builder 只跑一次**。任何要在浮层里更新的东西，
  都必须在浮层**内部**订阅（`sectionNotifier` / `settingsChanges` 就是这么来的）。
- **`request.url()` 带查询串**，而路由是精确匹配 —— 已统一在请求入口 `strip_query`。
  新加端点别假设自己能看到 `?`。
- **iframe 里的 canvas 自带不透明背景**，父页画的舞台底色会被盖住 —— 所以底色由渲染面写
  （`sync.stageColor`）。
- **后端的「省略 = 删除」语义**：`AppSettings::merge_into_toml` 会删掉「期望快照里没有的键」。
  写盘点必须传**完整快照**（`apply_patch` 返回的就是），别传部分对象。

## 10. 追加（交接之后、用户真机用出来的第 12 个 bug）

**用户原话**：「前端链路有些是断裂的，比如我确实无法使用设置（可以唤醒，但无法点击和
上下滑动），疑似和舞台 live2d 抢指令优先级了。」——**猜对了**。

| 项 | 内容 |
| --- | --- |
| 根因 | 舞台是 `<iframe>` 平台视图。Flutter Web 的**两张画布都是 `pointer-events: none`**，真正接指针的是 iframe 这个 DOM 元素，而它在 DOM 里**排在画布之上**。指针落在舞台区域 → 事件进 **iframe 自己的文档** → 父页（Flutter）一个都收不到。于是 Flutter 把控件**画**在了 iframe 之上，却**接不到**那一块的指针：设置浮层矩形 `[349,190,560,456]` 压在 iframe `[169,52,768,594]` 上，而 `elementsFromPoint(500,300)` 的答案是 `IFRAME`。 |
| 影响面 | medium 下**几乎整块设置浮层**、断线横幅的「点此重试」、舞台右下角缩放四键、加载失败覆盖层的「重试」——全部「看得见、点不着、也滑不动」。`expanded` 的内联侧板、`compact` 的抽屉同理。 |
| 修法 | `lib/live2d/stage_pointer_interceptor*.dart`（新）：在控件**下面**垫一层透明 `<div>` 平台视图（`flt-platform-view` 排在 iframe 之后 ⇒ 指针回到父页）。与 flutter/packages 的 `pointer_interceptor` **同法**（flutter/flutter#190574）；本项目运行时依赖只有 `flutter + http + web`（`shell/README.md` §依赖约束），所以自带一版。**零新依赖。** |
| 规矩 | **以后任何压在舞台上的可交互控件都必须套 `StagePointerInterceptor`**（也写进了 `AGENTS.md` 前端层约定）。`test/stage_pointer_interceptor_test.dart` 把已知接线点逐个钉住——漏套不报错，只会点不着。 |
| 仍然点不着 | `showModalBottomSheet` 的**模态障碍层**（「点空白关闭」）与**拖拽把手**：它们在 `builder` 子树**之外**，垫层罩不到。要一起修就得在设置打开期间铺满整块舞台，代价是「设置开着时还能拖模型」一起没——先不换。取舍写在 `StagePointerInterceptor` 头注与规格 §13.12④。 |
| 文件 | `lib/live2d/stage_pointer_interceptor{,_web,_stub}.dart`（新）、`lib/app/app_shell.dart`、`lib/app/nav_host.dart`、`lib/ui/stage_host.dart`、`lib/live2d/live2d_stage.dart`、`test/stage_pointer_interceptor_test.dart`（新） |
| 门禁 | `flutter analyze` 无问题 / `flutter test` **618 通过 0 失败**（610 + 8）。产物已重建（`--base-href /app/ --no-web-resources-cdn`；服务端按请求读盘，不必重启）。 |

**真机复验**（浏览器工具，本机 18080）：点 ✕ **关掉了**设置浮层；点「放大」→ 读数
**100% → 110%**（模型同步放大）；断线时横幅区域的命中元素不再是 `IFRAME`；
舞台左侧空白区**仍是** `IFRAME`——模型拖动（`sync.clickEnabled`）没有被牺牲。

**没做到的**：本机没有 `xdotool`，浏览器工具也只能按 uid 点击，所以无法注入

## 11. 追加（2026-09-11 晚）：错误可观测性 —— 「后端出错无具体错误代码」的三条断线

用户第二次报障：「后端出错无具体错误代码 / 改动提示词就崩了 / 你看看后端日志，
如果没有说明后端日志不够细」+「前端无法知道错误信息」。**三条全对**，
而且第三条是**结构性**的（不是配置问题）。

### 11.1 诊断（都可复现）

| 说法 | 查证结果 |
| --- | --- |
| 「后端日志不够细」 | 日志文件当时只有 9 行（全是启动 + 热重载）。`web_api/dispatch.rs` **一行请求日志都没有**；链路错误走 `println!`，**不进 tracing 文件 sink** |
| 「无具体错误代码」 | `ErrorKind` 只有 `Display` 散文（`上游非成功状态 401 Unauthorized: …`），没有码 |
| 「前端无法知道错误信息」 | `AppEvent` **没有错误变体**，`app_event_to_ws_frame` 没有 `error` 分支 → WS **从来不发** `error` 帧。前端 `WsErrorEvent` 类从写下那天起永远收不到实例 |
| 「改动提示词就崩了」 | **改提示词本身不失败**：10 组取值（空/引号/`"""`/反斜杠/多行/控制符/20k/CRLF）全部 200 且往返一致。当前那条是 `llm_upstream_401`，根因是**进程环境没有 `DEEPSEEK_API_KEY`**（直接跑二进制不会 source `./.env`） |

### 11.2 顺带查出的**真** bug（与「改提示词」直接相关）

手改 `live2d-ai.toml` 后，`file_watcher` 只 `supervisor.reload()`（重建 client），
**没有**刷新 `StatusContext` 快照 →

1. `GET /api/v1/settings` 回旧值（界面显示 ≠ 磁盘内容，**已实测**）；
2. 下一次界面「保存」以旧快照为基准整份写回 → **手改的提示词被静默覆盖**。

修法：`StatusContext::refresh_from_disk`，file_watcher 的 reload 后调用；
PATCH 路径改用同一函数。解析失败保留旧快照 + `warn`。

### 13.2 本轮新增的坑

- **`Error::status` 是 `pub(crate)`**：跨 crate 测试要造状态错误，直接用

- **前端 `error` 帧有两条消费路径**：`UiStateTracker`（**上屏那条**，`main.dart`
  里是 `_ui.errorMessage ?? _chat.error`）与 `ChatController`。改错误展示必须同时改
  两处，或抽成共用函数（本轮抽了 `formatWsError`）。**只改 `ChatController` 会出现
  「聊天面板有码、顶部横幅没码」**——实测过。
- **用户手改配置文件后 `GET /api/v1/settings` 必须跟随磁盘**（§11.2）。排障先
  `grep -n system_prompt live2d-ai.toml` 再对接口，两边不一致就是这条。
- **验证用的服务是后台 job**：`bash-9`，端口 18080。stdout 在 `cache/run/server.log`，
  tracing 在 `cache/xdg/live2d-ai/logs/live2d-ai.log.<日期>`。换二进制**必须重启**
  （Rust 编进进程）；前端只重建产物即可（服务端按请求读盘）。
