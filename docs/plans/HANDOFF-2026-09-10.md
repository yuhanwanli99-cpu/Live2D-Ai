## 本轮交付

### 1. 核心链路闭环

LLM 流式 → 按句切分 → TTS 流式合成 → PCM 分片 → WS 广播 → 浏览器 WebAudio 播放 +
浏览器侧真实 RMS 驱动 Live2D 口型。前端为 Flutter Web（`shell/`），由 Rust 在 `/app/` 同源托管。

### 2. 音频「很吵」根因修复（**重点，勿回退**）

三个缺陷，第 2/3 个是修第 1 个后才会暴露的连带缺陷：

| # | 缺陷 | 修复 |
| --- | --- | --- |
| 1 | 用 WS `audio.start`（**每 200 ms TTS 分片的首帧**）重置播放时间轴，而分片是 1 ms 级突发到达，上片仍在播 → 最多 **17 个音源同时发声**、重叠 529 对，逐样本相加成削波杂音 | 时间轴只前进；只有「排空」才锚定 `now`；轮次边界交给 epoch + `interrupt()` |
| 2 | 口型在**到达时**释放电平 → 超前均值 1.45 s / 峰值 5.17 s | `LevelTimeline` 按**播放时刻**到期释放 |
| 3 | 停止按钮走 `new_epoch`，客户端未监听 → 停止后旧音频继续响到提前量用尽 | `new_epoch` 立即 `audio.interrupt()` |

硬度对照（真实客户端 CDP 打桩，记录产品代码发出的每个 `when`）：

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| 重叠对 | 529 | **0** |
| 最大同时发声 | 17 | **1** |
| 累计重叠 | 9.79 s | **0.00 s** |

### 3. 服务端 `audio.start` 语义修正

`Broadcaster` 按 epoch 跟踪，`start=true` 只在**每轮语音首片**出现（修复前每 200 ms 分片都发）。
实测一轮 598 帧 / 11.96 s 音频 → `start=true` 恰好 1 次（修复前应为 61 次）。

### 4. 其它一并落地

- 模型渲染**纵向被压扁**的比例缺陷：`layout_transform` 曾按轴分别缩放，已改为统一缩放（非方形画布不再变形）。
- 聊天「无返回」：前端 `shutdown_ready` 永久闩锁导致永不重连；DeepSeek flash 只调工具不说话。
- Flutter Web 静态托管 `/app/`（`flutter_app.rs`，SPA fallback + MIME + canonicalize）。
- Mod 边界：`local-llm` / `local-tts` 为 OpenAI 兼容端点适配器（探活 + 写 settings + 热重载，默认**不** spawn）。
- 许可证：**AGPL-3.0-only** 保持原状（`Apache-3` 不存在，相关改动已作废）。

## 关键陷阱（踩过的坑，别再踩）

1. **绝不要用 `audio.start` 重置播放时间轴**。它不是轮次起点。`schedule.dart` 与
   `audio_schedule_test.dart` 里有回归钉子：改回去测试立刻变红。
2. **`epoch` 只在 stop 路径推进**，正常完成轮次不变——不要指望靠 epoch 变化区分普通轮次。
3. **前端改动必须重新 `flutter build web --release --base-href /app/`** 才生效；
   静态文件由服务端按请求读盘，所以**前端改动只需重建、不必重启后端**；`src/*.rs` 改动才需重启。
4. **`pkill -f "[l]ive2d-ai-desktop"` 必须单独一次调用**（与同一条命令里的 `pgrep` 会自匹配）。
5. **trunk 构建**需 `unset NO_COLOR`，并在有代理时 `export CARGO_HTTP_PROXY=$https_proxy`。
6. **运行后端需要 `DEEPSEEK_API_KEY` 在环境里**（不是 argv，也不是配置文件）。用 `scripts/ignite.sh`。
7. **headless Chrome 的点击坐标依赖视口**：必须先用
   `Emulation.setDeviceMetricsOverride {width:1258,height:646}` 锁定几何，否则会「点空」——
   表现为截图正常、WS 已连接，但 `starts: 0`。
8. **`build/` 已在 rust-ratio 排除名单里**（否则 Flutter 产物会把占比压到 37%）。
9. **CDP 打桩要用新建标签页**（`PUT /json/new`），不要复用旧标签页——
   `addScriptToEvaluateOnNewDocument` 会残留，导致 `start` 被重复记录。
10. **不要用「前端产物 md5」判定修复是否在线**。本仓库可能**并行有多个 agent 在工作**
    （交接时即观察到他人新增 `shell/flutter/test/display_prefs_test.dart` 并重建了前端）。
    重建会改掉产物哈希，但源码修复（`audio_player.dart` / `schedule.dart`）仍在。
    唯一可信判据是直接跑**重叠分析**：重叠对 = 0 且最大同时发声 = 1。
11. **别记 PID、别假设「服务在跑 = 你启动的那个在跑」**：本仓库**可能并行有多个 agent**，
    它们会互相重启后端——这才是「SIGTERM 后约 1 秒又活了」的真实原因。
    **没有外部守护进程**（复核证据：无 systemd/cron/docker/watchdog；
    在 18099 起诱饵服务并 SIGTERM，5 秒内无人接管）。

  `TextDelta` 分支，测试会立刻变红。
