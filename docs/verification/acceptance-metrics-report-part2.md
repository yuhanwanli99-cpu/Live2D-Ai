## 5. 可直接执行的验收评分卡

> 每条评分卡均为「低成本、可重复」，个人开发者无需 30 人团队即可落地。

---

### 评分卡 A：TTS 自然度 MOS 听测卡（正式版 ≥30 人 / 个人版 ≥5 人）

**准备**
- 候选：2 个 TTS 引擎 + **1 个人声黄金基准**（同一句话真人朗读，作拟人参照）。
- 文本：5 句固定文本（对话性+陈述性+疑问+带节奏长句）+ 10 句中文专项（多音字/轻声/儿化）。
- 量表标签固定写清楚（5=优秀…1=很差），避免歧义。

| # | 文本 | 类型 | 自然度 1–5 | 发音准确 1–5 | 韵律自然 1–5 | 备注 |
|---|---|---|---|---|---|---|
| 1 | 喵~主人今天也元气满满呢！ | 对话/俏皮 | | | | |
| 2 | 这是一段陈述性的介绍文字，用来测试陈述的自然腔调。 | 陈述 | | | | |
| 3 | 你真的要现在出发吗？ | 疑问 | | | | |
| 4 | （带停顿和节奏的长句，测换气/断句） | 长句 | | | | |
| 5 | （随机一段被测试语音） | 对照 | | | | |
| 6–15 | 中文专项（儿化/轻声/多音字/数字串/网络语） | 专项 | | | | |

**统计与判据**
- 算每个引擎的**均值±置信区间**；个人版同一语音测 2 遍看自洽。
- 比较引擎间是否存在统计显著差异（30 人版）。
- 门禁参考：DNSMOS≥3.5 / 人工 MOS≥4.0 为建议"可接受"起点（须与你的人声基线标定，见主报告 §1.1/1.2 警示）。

**说明的来源**：量表 P.800（https://www.itu.int/rec/T-REC-P.800-199608-I）；>30 人 / <20 人陷阱（https://www.isca-archive.org/interspeech_2015/wester15c_interspeech.pdf）；人声黄金基准（https://www.isca-archive.org/interspeech_2024/edlund24_interspeech.pdf）。

### 评分卡 B：中文专项发音卡（产出发音正确率 %）

**使用步骤**
1. 用主报告 §1.4 的 ~50 句中文字元测试集。
2. 每句听写（或 ASR 识别）→ 判定「对/错」。
3. 指标：
   - **发音正确率 = 全对句数 ÷ 总句数**（建议门禁 ≥90%，以你语料标定）
   - **分类错误率**：分别统计 儿化 / 轻声 / 多音字 / 数字串 4 桶的错误率，定位 TTS 的薄弱项。

**说明的来源**：中文 TTS 评测方法论（https://www.jac.ac.cn/article/doi/10.15949/j.cnki.0371-0025.1998.01.003）、教育部/国家语委 2006 标准（https://yywz.sues.edu.cn/_upload/article/files/d4/17/116e9f864a35b845bc5a98c1183b/cb807dfb-57dc-4b83-9bab-491c077fb31e.pdf）。

### 评分卡 C：表现力（情感 TTS）专项听测卡

**准备**：选定 3 种情感（例：开心 / 伤心 / 撒娇），各 5 句=15 条录音；固定的上下文框架（避免框架影响主观分）。

| # | 情感 | 文本 | 自然度 1–5 | 情感传达准确 1–5 | 情感强弱恰当 1–5 |
|---|---|---|---|---|---|
| 1 | 开心 | 太好了，终于等到你回来啦！ | | | |
| 2 | 伤心 | 呜……一个人待了好久。 | | | |
| … | 伤心 | … | | | |
| … | 撒娇 | 主人~就陪我玩一会儿嘛。 | | | |

**自动辅助**：用中文情感识别模型给每条打预测标签，算 **情感 Top-1 命中率 %**（辅助值，非人工替代）。

**来源**：表现力评价困难点（https://www.isca-archive.org/ssw_2021/gutierrez21_ssw.pdf）、上下文影响（https://www.isca-archive.org/interspeech_2024/edlund24_interspeech.pdf）。

### 评分卡 D：LipSync 口型同步量化卡（每句测对齐偏移 ms）

**自动法**
1. 选 10 句含清晰元音起始的音频。
2. 录屏（≥60fps）→ 音轨 onset 与口型张合 onset 逐段对齐。
3. 记录：每句偏移、平均偏移、P95。

| # | 句（文本） | 音频 onset(ms) | 口型 onset(ms) | 偏移(ms) | 是否 >125ms 缺陷 |
|---|---|---|---|---|---|
| 1 | 喵~ | | | | 是 / 否 |
| … | … | | | | |

**验收判据**：平均偏移 **≤45ms**；**任一句 >125ms 判缺陷**（BT.1359-1）。附人工 1–5 同步分（补感知）。

**来源**：ITU-R BT.1359-1（https://www.itu.int/rec/R-REC-BT.1359-1-199811-I/en）与汇总（https://www.tvtechnology.com/news/managing-lip-sync）。

### 评分卡 E：渲染与表情自然度卡

| 检查项 | 采集 | 判据 | 判定 |
|---|---|---|---|
| FPS 稳定性 | 60s 对话渲染帧统计 | 目标 ≥30fps；<25fps 不达标 | 通过/不通过 |
| 眨眼周期性 | 60s 录像，统计眨眼次数/分钟 | 落在通透静息区间（~12–20次/分，常识参考） | 通过/警示 |
| 眨眼过渡 | 逐帧看过渡是否有 ease-in/out | 无明显跳变 | 通过/不通过 |
| 表情切换平滑 | 计时表情过渡时长 | 在合理区间（~100–300ms 经验），无瞬跳 | 通过/警示 |
| 表情自然度（主观） | 人工 1–5 | ≥4 视为自然 | |

**来源**：Live2D FPS 15/30/60/120（https://docs.live2d.com/en/cubism-editor-manual/physics-operation/）、眨眼自动化（https://docs.live2d.com/en/cubism-sdk-tutorials/eyeblink/）、运动平滑（https://docs.live2d.com/en/cubism-editor-tutorials/motion-hint/）、眨眼生理（https://la.disneyresearch.com/wp-content/uploads/Modeling-and-Animating-Eye-Blinks-Paper.pdf）。

### 评分卡 F：对话多轮评测表（20 轮）

**准备**：5 个猫娘人设场景×4 轮=20 轮；评审 ≥2~3 人，按 5 维度 1–5 打分。

| 场景 | 轮 | 用户输入(示例) | 相关性1–5 | 连贯性1–5 | 人设一致1–5 | 有用性1–5 | 无害1–5 |
|---|---|---|---|---|---|---|---|
| 打招呼 | 1 | 我回来啦~ | | | | | |
| 打招呼 | 2（追问） | 今天累不累？ | | | | | |
| 日常 | 1 | 你能陪我聊聊吗 | | | | | |
| 伤心安慰 | 1 | 我今天很难过 | | | | | |
| 俏皮调侃 | 1 | 喵你只会喵喵叫吗 | | | | | |
| 主动推荐 | 1 | 有什么好玩的？ | | | | | |
| …四轮累计… | | | | | | |

**多轮上下文回检**（第 4 轮）：承接第 1 轮给出的关键事实，作答是否命中 →
- **事实回检命中率 = 命中数 ÷ 回检问题数**（需记录场景内姓名/喜好/时间等事实）。
- 加 LLM 裁判「多轮连贯性 1–5」。

**来源**：G-Eval 维度 1–5 框架（https://aclanthology.org/2023.emnlp-main.153.pdf）、MT-Bench-101（https://aclanthology.org/2024.acl-long.401/）、MT-Eval 多轮（https://aclanthology.org/2024.emnlp-main.1124.pdf）。

### 评分卡 G：人设一致性 OOC 检测卡（双通道）

**双通道**：
- **规则通道**：关键词/禁止口吻清单（如出现"作为AI助手/我是语言模型/我不能"即判 OOC）。
- **LLM 裁判通道**：对每轮回复给 1–5「人设贴合度」，<3 记为疑似 OOC。

| 场景/轮 | 回复 | 规则通道(命中的词) | LLM贴合度1–5 | 是否 OOC(需≥2人人工确认) |
|---|---|---|---|---|
| 打招呼/1 | … | | | 是/否 |
| … | | | | |

**指标**：**OOC 占比 = OOC 回复数 ÷ 总回复数**。AI 裁判结论须人工复核（LLM 判人设不可靠）。推荐长期**跑回归**：设 OOC 占比上限（如 ≤5%，以基线标定）。

**来源**：OOC 检测（https://aclanthology.org/2025.findings-acl.1349/）、PersonaArena（https://aclanthology.org/2026.findings-acl.471.pdf）、LLM 裁判不可靠（https://openreview.net/forum?id=drdrFhKYjP）。

### 评分卡 H：端到端延迟埋点卡

| 阶段 | 指标 | 采样方式 | 目标(P50) |
|---|---|---|---|
| LLM 首 text token | TTFT | 埋点 | ≤800ms |
| TTS 首个音频字节 | TTFA | 埋点 | ≤1s |
| 文字提交→首个音频 | 端到端 | 埋点 | ≤2s |
| （若 PC 有语音）口到耳 | 端到端全链路 | 埋点 | 参考 ~1.1s 预算 |

- 每类统计 **P50 / P95**，发版前后对比。
- **来源**：TTFT（AWS: https://docs.aws.amazon.com/wellarchitected/latest/agentic-ai-lens/agentperf02-bp04.html）、TTFA<1s（NVIDIA: https://perspectives.nvidia.com/nemotron-speech/task/faq/...）、端到端预算（Twilio: https://www.twilio.com/en-us/blog/developers/best-practices/guide-core-latency-ai-voice-agents）。

### 评分卡 I：可用性 & 满意度（SUS + CSAT）

- **SUS**：≥5–8 名用户填 10 题（工具 sus.tools 计算），验收 **≥68**，发布目标 ≥72–80。
- **CSAT**：每交互弹 1 题「这次对话满意吗？」，验收 **≥75%**。

**来源**：SUS（https://measuringu.com/sus/ 与 benchmark）、CSAT（HubSpot: https://blog.hubspot.com/service/customer-satisfaction-score）。

## 6. 优先级建议（个人开发者：成本低、见效快）

### P0 —— 立即上（代码级，半天~1天，自动化，不占人力）

| 评分卡 | 指标 | 为什么优先 |
|---|---|---|
| B（DNSMOS）+ 1.2 WER | **客观 MOS + 可懂度** | 全自动，批量冒烟门禁，立刻能发现 TTS/ASR 回归 |
| H（TTFT/TTFA） | **延迟埋点** | 埋点即可，快速暴露 LLM/TTS 链路瓶颈 |
| D（LipSync 偏移） | **口型同步** | 门槛就是感知阈值，直接决定体验；脚本可测 |
| A（个人版 MOS） | **≥5 人 MOS 听测** | 最低成本拿到人耳基准，配合 DNSMOS 标定 |

### P1 —— 中成本，有明确验收价值（发版前必做）

| 评分卡 | 指标 | 说明 |
|---|---|---|
| F（20轮对话） | **人工对话质量** | 发版前必须人工复核，维度量化可追踪迭代 |
| G（OOC） | **人设一致性** | 猫娘人设是本产品核心卖点，OOC 即致命 |
| C（表现力） | **情感传达** | 情感是差异化点，值得专项测 |
| E（渲染/表情） | **帧率+眨眼+过渡** | 视觉体验关键，已有 Live2D SDK 指南 |
| I（SUS/CSAT） | **可用性&满意度** | 需真人用户，C 端验收必收 |

### P2 —— 锦上添花 / 选做

- 说话人相似度 SS（克隆场景）
- BERTScore（需参考语料）做翻译/改写回归
- 中文情感识别自动命中率（辅助）
- 多轮长上下文压力测试（>16 轮）

### 关键方法论提醒（免费但有质量门槛）
1. **MOS 不要只用 DNSMOS**——DNSMOS 是廉价代理，发版前务必做**≥5 人真实听测**并与 DNSMOS 标定，因为 P.800 主观分才是金标准。
2. **人设一致性不要只信 LLM-as-Judge**——文献明确 LLM 判人设会失败，**必须人工复核**。
3. **每个"阈值"先用你自己的语料/基线标定 3 次以上**再固化成验收门禁，报告中给出的 P0/P1 目标多为项目目标区间（源自权威来源边界），非信条。
4. 所有听测必须**固定上下文框架**、**写清量表标签**，否则结果不可比、不可复现（Sources 见主报告 §1.1/1.3）。
