## 1. 这一版要解决的问题

克隆仓库、按发布说明起服务之后，**不开箱**：

- 舞台没有模型（`assets/models/*` 被忽略，得自己导入）；
- 没有能出声的 TTS（端点要自己配，本地引擎要自己找）；
- 注册表里挂着一个**没适配**的 CosyVoice3 引擎；
- 界面上摆着密钥入口，仓库里却没有 Key，也没说去哪申请。

## 2. 四件事

### 2.1 白模型（bai）进仓库

- `assets/models/bai/` 的**渲染必需文件**随仓库分发：`MODEL_LICENSE.md`、
  `runtime/bai.model3.json` / `bai.moc3` / `bai.cdi3.json` / `bai.physics3.json`、
  `runtime/bai.16384/texture_00_4096.png`（`bai.model3.json` 的 `Textures` 点的是这一张）。
- `.gitignore` 为 `assets/models/bai` 开**目录例外**：`git check-ignore -v` 对
  `bai.moc3` 与 `texture_00_4096.png` **没有输出**（= 不匹配任何规则）。
  未被 `model3` 引用的 `runtime/bai.16384/texture_00.png`、以及 Cubism/VTube 工程残留
  （`bai.vtube.json`、`items_pinned_to_model.json`）**继续忽略**。
- 写法刻意是「目录例外 + 逐项排除」而不是「通配再 `!` 回填」：`!` 回填会让
  `git check-ignore -v` 对**已放行**的文件也打出一行，而验收要求那两个静默。
- **许可边界（不要读成「作者已授权」）**：作者原六条条约**一字不改**保留；
  `MODEL_LICENSE.md` 新增「本仓库的特殊说明」——版权归原作者、代码许可不覆盖模型文件、
  放进仓库只为克隆后可渲染、使用/二创/直播的纠纷由使用者自负，**权利人提出可核验的
  删除要求后 24 小时内从 `main` 去掉并推送、已发出的该 tag 同期限内删除远端引用、
  不改写更早历史**。
- `BUILTIN_MODEL_URL` 仍指向 `/models/bai/runtime/bai.model3.json`，
  `active_model_id` 在没有 `model_registry.json` 时回落它 ⇒ **新鲜克隆不用先导入**。
- 白模型**不走 LFS**（最大约 8.6 MB，普通 git）。

### 2.2 MeloTTS 缺省启用

- `cli_entry::default_mods_manifest` 收录 `local-tts-melo`：`enabled: true` +
  `launch_mode: "with_app"` ⇒ **开机拉起**仓库内 `melo/start.sh`。
  `external-input` 继续缺省启用；persona / voice-input / memory / director 仍缺省停用。
- 出厂 `[tts]` 缺省（代码里 `TtsSettings` 的 `serde(default)` 与
  `live2d-ai.toml.example` **同一份值**）：

  | 键 | 值 |
  | --- | --- |
  | `base_url` | `http://127.0.0.1:8091/v1` |
  | `voice` | `ZH`（`melo/weights/config.json` 的 `spk2id` 键） |
  | `response_format` | `pcm` |
  | `sample_rate` | `44100`（同一份 config 的 `sampling_rate`） |
  | `channels` | `1` |
  | 密钥 | **不设**（`api_key_env` 缺省 `None`） |

  `AudioSpec::DEFAULT_SAMPLE_RATE`（播放侧 24 kHz）**没动**：那是另一个口径。
- **Mod 仍然不写 `[tts]` 的任何键**（`apply_settings` 调用次数恒为 0）：
  出厂 `[tts]` 只是恰好指向它。
- `checkpoint.pth`（198 MiB）走**既有那一条 Git LFS 规则**（`.gitattributes`
  的 `crates/live2d-ai-mod-local-tts/melo/weights/checkpoint.pth`），从 Hugging Face
  `myshell-ai/MeloTTS-Chinese` @ `af5d207a` 拉取；`config.json` 仍是普通 git 文件。
  **没有裸 `git add`**。
- **子进程立刻非 0 退出 ⇒ `start` 返回 `Err`、Mod 状态 `Failed`**，错误里带
  **脚本印出的原因**（子进程 stderr 的尾巴；进程形态从 `stderr = inherit` 改成
  「接管道 + 专用读线程读干 + 同时透传到宿主终端」，理由与红线写在
  `crates/live2d-ai-mod-local-tts/src/child.rs` 头注）。1 秒观察窗口
  （`IMMEDIATE_EXIT_GRACE`）；**退出码 0 也算失败**（立刻退出 = 没在听端口）；
  观察失败（`try_wait` Err）同样 Err 并停掉子进程。
  回归：`crates/live2d-ai-mod-local-tts/src/tests_start_failure.rs`（5 条）。
  这条正是 `docs/audit/2026-10-09-silent-errors/FINDINGS.md` 允许修的那**一条**，
  其余 S-000…S-007 一行未动（见该文件文末追加）。
- `bert-base-multilingual-uncased` **不入库**：缺它就是失败（错误里逐字写缺的是它），
  不静默下载完还声称开箱。

### 2.3 CosyVoice3 封存

- `local-tts`（界面名 `本地tts_CosyVoice3-0.5B`）**移出 `AVAILABLE_MOD_FACTORIES`**；
  crate 与 `engine/` **留在树上**（可编译可测），crate 头注写明「封存，还要适配，
  未适配前不要挂回」。缺省 manifest 不含它，开机不拉起。
- 工厂数 **7 → 6**：`mod_count_is_seven` → **`mod_count_is_six`**，
  `mod_factory_ids_match_expected` 的 id 集合同步
  （`external-input` / `persona` / `voice-input` / `memory` / `director` / `local-tts-melo`）。
- 前端那一句操作规则改指新引擎：
  `扩展 本地tts_MeloTTS 只拉起进程，不会改写这个地址。`
- 现行句更新：`docs/architecture/tts-is-core.md` §7（**新增**，文末）、
  `docs/architecture/mod-product-chain.md` §5；§1–§6 与历史发布说明**不改**。

### 2.4 不带 LLM Key

- 仓库**不提供、不提交**任何 LLM Key。`[llm]` 仍是
  `base_url = "https://api.deepseek.com/v1"` / `model = "deepseek-flash"`。
- `live2d-ai.toml.example` 的 `api_key_env` 写成 **`DEEPSEEK_API_KEY`**，
  值住 `.env`（本机文件，不进 git），**出厂为空**（= 不发送 `Authorization`）。
- 设置 →「模型服务 → 语言模型」的密钥那一行**只留一句**：
  `到 DeepSeek 申请自己的 Key，填到下面。` 没有 Key 时的错误仍是**现有的 401 码**，
  没有换一套无码文案。
