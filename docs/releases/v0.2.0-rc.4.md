## 1. 阶段3：单一驱动者（D10–D13）

## 2. 阶段4：表演协议 v1（D22–D39）

| 面 | 内容 |
| --- | --- |
| **文本** | `speak`（可改写）退役为 **`segments`（只切分原文、逐字不变、拼接 == 原文）**；上屏 == 送 TTS == `clean_for_tts(段)`（D23） |
| **段/句** | 段 ↔ 句 **1:1**（`seg:N` ≡ `sentence_seq==N`，不再二次切分；回退路径仍走 `SentenceAssembler`，D22）；空白段**不跳号**（D24） |
| **表演字段** | `body` / `head` / `expression` 三族，同类 **add**、立即生效不排队（D26 批内 add / 跨批次 replace）；`expression` **只写五官**（V3） |
| **时间轴** | **唯一基准 = 音频播放时钟**：新增 `stage-clock` 消息（30ms），渲染面用它替代 `performance.now()`；段 A 回落墙钟 |
| **回执** | 渲染面**事件级** ack 四条 + `segment-ended`（含最终生效轴值 / `clamped` / `degraded` / `reason`） |
| **会话 baseline** | baseline 绑会话（`session_scope` 兄弟字段）；停止 / 新消息 = 清动作 + 表情 + TTS 待播 + 回 baseline，**不补帧** |
| **兼容** | `action_cue` 帧 / `preset_id` / `speak` **一律不删**；只增不改（V11） |

## 3. 阶段5：导演可观测 + 单模型动作强度（D40–D48）

- **导演可观测（dev_mode）**：设置 → 开发工具新增一块四栏——**A 决策参数**（emotion/intent/suggested_tts/preset_id + 计数）、
  **B 事件流**（`action_cue` / 渲染面 ack / `stage-clock` / `turn_state` / `error`，环形缓冲 200 + 类型过滤）、
  **C 传参对照**（前端发出的 `preset` 请求 **vs** 渲染面 ack 的**最终生效值**）、
  **D 送 TTS 文本**（`text_delta` 与日志端点 `sentence_ready` 并排，来源标注）。**不新增任何 WS 帧**（D41）。
- **单模型动作强度**：`live2d-ai.toml` 新增可选 `[action.models.<model_id>]`，
  `head_scale`/`body_scale`/`expression_scale` **三键各自回落全局**（D40，修正 O10）；
  UI = 「本模型覆盖」开关 + 三条滑条 + 「恢复跟随全局」；渲染面**零改动**。

## 7. 用户肉眼验收最短路径（Windows 浏览器，单个客户端）

1. `cd /home/skystar/Live2D-Ai-l1 && ./scripts/ignite.sh`；浏览器开 `http://127.0.0.1:18080/app/`。
2. **导演可观测**：设置 → 打开 `dev_mode` → 开发工具 → 「导演可观测」：发一句话，A 栏出现决策、B 栏出现 `action_cue`、
   C 栏出现「请求 vs 生效」、D 栏出现送 TTS 文本。
3. **单模型幅度**：外观与互动 → 动作幅度 → 开「本模型覆盖」→ 把 head 拉到 1.2 → HUD `scale h1.20`；
   点「恢复跟随全局」→ 回 0.75。
3. **口型/声音同拍**与**说话中途按停止**（旧语音当场断、不补播）仍需你本人听。
