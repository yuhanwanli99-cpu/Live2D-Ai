## 1. 对外新增

### 1.1 发现文档：GET /.well-known/agent-card.json

- 请求时生成；version = Cargo 包版本 0.3.1（agent 版本，不是协议版本）。
- url / supportedInterfaces 都**只**指向 http://127.0.0.1:<port>/api/v1/a2a；
  不写上游 base_url、不写密钥、不写 .env。
- capabilities.streaming = false、pushNotifications = false；
  defaultInputModes / defaultOutputModes = ["text/plain"]。
- 一个 skill：id llm-chat，说明「把文本交给当前已配置的对话模型，回文本」。

### 1.2 JSON-RPC 端点：POST /api/v1/a2a

- 只收两个方法：message/send、tasks/get；消息只收 role=user 的 kind=text parts
  （多段 text 用换行拼成一段），空文本 / 非 text part 回 -32602 且不打上游。
- message/send 成功回一个 completed Task：
  - 正文在 artifacts[0].parts[0].text（A2A 0.3.0 规范：completed SHOULD 用
    artifacts 回传生成物）；
  - 同时放一份在 status.message（执行单要求的「一条 agent 消息、一个 text part」）；
  - 两处逐字相同，有回归断言。
- tasks/get 按 task id 从**进程内**任务表取回：上限 32 条、FIFO 淘汰、不落盘、
  进程重启即消失；未知 id 回 -32001 TaskNotFound。
- 上游复用现有 OpenAiClient::chat_stream（stream=true）：只累加 TextDelta，
  **丢弃 ReasoningDelta**（思考不进 A2A 正文）；请求体不带 tools / tool_choice /
  functions（新测试文件断言，未撑大 llm.rs）。
- 上游失败只回稳定错误码（如 llm_upstream_401），不把上游 body / 密钥回出去。

## 2. 明确不实现（返回 JSON-RPC 错误，没有半截 SSE）

- message/stream、tasks/cancel、tasks/resubscribe、tasks/list、
  agent/getAuthenticatedExtendedCard → -32004 UnsupportedOperation；
- tasks/pushNotificationConfig/* 整族 → -32003 PushNotificationNotSupported；
- 其它未知方法 → -32601 Method not found；
- 不接 gRPC、不接 HTTP+JSON REST、不收 file / data part、不做推送。
- **与 0.3.0 规范的一处偏差（如实记录）**：0.3.0 把 tasks/cancel 列入 MUST；
  本版按执行单「不实现取消」显式拒绝（-32004），不假装成功、不出半截流。

## 3. 协议版本与 supportedInterfaces（版本拼接的取舍，如实说明）

- 数据形状钉在 A2A **0.3.0** 的 JSON-RPC 绑定：kind 判别、role user/agent、
  status.state completed、parts [{kind:"text"}]。
- supportedInterfaces / protocolBinding 是 A2A **1.0** 字段，0.3.0 卡片里没有；
  执行单明确要求带上，因此卡片 =「0.3.0 必填字段齐全 + 多带一个 1.0 的
  supportedInterfaces（指向同一端点）」。**不是** 1.0 客户端兼容承诺：真正切 1.0
  要整体换数据形状（role 枚举 / Part 无 kind），不在本块。
- 真正按 0.3.0 解析的客户端只看 protocolVersion + url + capabilities + skills，
  多出来的字段被忽略即可。

## 4. 边界与安全

- POST 与其它 mutating 路由同一套校验：Content-Type: application/json +
  loopback 同源 Origin（无 Origin 时按 LIVE2D_AI_ALLOW_NO_ORIGIN 工具模式）。
  **这意味着外部 agent 必须同机（或经反代）调用**——执行单规定的本地边界。
- 监听仍只绑 127.0.0.1；响应 / 日志 / 卡片不含密钥；日志只记 task id 与字符数，
  不记正文。
- message/send 要等上游整段回复：run_request_loop 仍是单线程循环，因此 A2A POST
  **派生工作线程**（spawn_a2a），不让一次 A2A 调用冻住 /app/ 与其它 API
  （有「慢上游时普通 GET 仍在 700ms 内完成」的 e2e 回归）。GET card 仍循环内直答。

## 5. 与皮套主链的隔离

- 不调 supervisor.say、不进句子装配、不进 TTS / 口型 / action_cue；皮套回合请求体
  没有新增 tools。
- [llm].mode = cloud | local 都按同一份配置调用；local 失败**不回退** cloud
  （没有第二份端点，也未新增；e2e 断言 local 失败只打一次上游）。
- 密钥仍只走 .env / secrets::lookup。
