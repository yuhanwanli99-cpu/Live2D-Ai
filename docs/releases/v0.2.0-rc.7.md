## 2. R7-a · 审计主发现 **F-0005-2**（重建放大链，唯一「最有价值的单点」）

**现象**：每个 WS `text_delta` → `ChatController.notifyListeners()` → main.dart 外层
`ListenableBuilder` → **整棵 `AppShell.build()` 重跑** → `_settingsSurface(...)` 在 build 里即时求值
→ **当前设置分区整棵重建 + 布局，即使面板处于关闭态**（`text_delta` 是毫秒级）。

**改法（选 A：缓存分区内容）**：`AppShell` 新增宿主状态代际 `settingsRevision`；
`AppShellState` 新增 `_settingsTick`（`settingsChanges` 通知次数，独立 `ValueNotifier` 自驱重建）；
两者 + `section` 组成 `_pane()` 的**缓存键** —— 键不变就返回**同一个 widget 实例**，
父级重建走到 `Element.updateChild` 被短路（不 build、不布局）。

**验收（可失败、确定性）**：`test/rebuild_scope_test.dart`
› `10 次聊天增量最多只让当前设置分区重建 1 次（F-0005-2）`
—— 实施者贴出的红-绿：旧实现 `Expected: a value less than or equal to <1> / Actual: <10>`（**+10**）；
最终实现实测增长 **0**（把断言临时收紧到 `equals(0)` 也绿）。
**承重性自证**：三处注入回红（缓存换回直调 → +10；拿掉「设置数据代际」→ 面板冻住；拿掉「宿主代际」→ 不刷新），
证明两个代际都是**承重**的而非装饰。

**同类守卫补齐**：聊天消息/流式仍上屏、错误横幅仍更新、设置打开/切分区仍生效、
Offstage 保活语义不变（`settings_panel_keepalive_test` 等 15 个文件 205 条针对性测试全绿）。

**如实标注未做到的部分**：**只挡住了「当前分区」这棵子树**；`AppShell.build()` 本身、
设置面板头部（分区 chip + 保存条）与 `ChatPanel` 仍会随 delta 重建。
要消掉那一层需要「外壳不再整体订阅 `_chat`」的更大重构（审计的改法 B），**本版未做**，
且**幅度未经真机 profile**（审计原文即标「机制高 / 幅度未核实」）——**没有冒充实测**。
