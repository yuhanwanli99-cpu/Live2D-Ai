### 3.4 正文兜底：同拍契约的**异常让位**（本版核心产品项）

**默认仍同拍**：健康路径上屏的闸门是「该句语音**已完整合成**」（`EngineEvent::SentenceVoiced`
→ WS `text_delta`，前端**追加**）；`EngineEvent::TextDelta`（LLM 原始增量）**只做控制台回显**。

**代价**：任何让某句凑不齐的原因（TTS 挂掉 / 合成失败 / LLM 中途断流）都会让**整轮一个字都不上屏**
——用户看到「模型没有返回」，而模型其实写完了正文。

**本版补的是失败轮出口**：

```text
健康轮（Completed）                        失败轮（Failed）
──────────────────────────                ──────────────────────────
… SentenceVoiced ──► WS text_delta（追加）   …
Terminal{Completed}                        Error(tts_*)
                                           TextFallback ──► WS text_fallback（**覆盖式**）
                                           Terminal{Failed}
```

四条判据（改之前先改文档）：① 只在 `Failed` 且已有正文时发（`Cancelled` 不补文字）；
② `text` 是**整轮正文**（不是残余），前端**整段设置**而不是追加（天然幂等；用「已上屏前缀」
推导残余会因切句器 trim 而算错）；③ 发在 `Terminal` **之前**，`Completed` 轮**永不**发
（抢不了健康路径的跑）；④ **没有**新增 `turn_id` 之类的跨层字段。

前端：`ChatController._applyTextFallback`（覆盖 + `ChatMessage.unfinished`）→ 气泡加一行
`kUnfinishedTurnCaption`（「未收尾：本轮语音未合成完…」），并且该标记**落盘**——刷新后那段
文字还在，就必须仍带这个限定。契约写进 [`core-chain-baseline.md` §2.1](../architecture/core-chain-baseline.md)。

### 3.5 真机验收又抓到一个缺陷（**已修 + 有回归**）

第一次真机「掐 TTS」验收时**兜底没生效**：WS 上只有 `error` + `turn_state`，界面是
「（生成失败）」。加临时探针定位到 `run_one_turn` Stage A 的 biased `select!`：

> `gen_fut` 的**最后一次轮询**可能在返回前同步塞进若干引擎事件（`send_event` 在缓冲
> 未满时立即完成）；而 select 一旦选中 `gen_fut` 臂就**立刻返回**，不会回头再 poll 排在它
> 前面的 `event_rx` 臂。于是这批事件留下，被收尾的 `drain_residual_events` **静默丢掉**。

`TextFallback` 是**第一个在收尾时同步发出**的业务事件，正好落进这个窗口（`Error` 由 TTS
worker 异步发、`SentenceVoiced`/`AudioChunk` 在引擎等网络时到达，所以历史上没暴露）。
修法：生成返回后先把通道里剩下的事件按**正常路径**排空再进 Stage B/C/D。

回归 `supervisor::tests_loop::failed_turn_delivers_generated_text_via_text_fallback` **已实测
「去掉修复即红」**（把 `turn.rs` 单独 stash 重跑，拿到的正是真机那份没有 `TextFallback`
的事件序列）。另有 `tts_transport_failure_also_falls_back_to_the_generated_text` 单钉传输层
失败（与上游 5xx 是不同的错误构造路径）。
