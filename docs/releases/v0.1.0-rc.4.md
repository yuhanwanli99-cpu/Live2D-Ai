## 2. Mod 产品链路（M0 → M4）

| 里程碑 | 交付 | 位置 |
|---|---|---|
| **M0** 契约钉死 | Mod 静态编译模型 / 契约面 / **加新 Mod 勾选表** / 正式版 Rust-C 规则 / 失败隔离 / 非目标 | 新增 `docs/architecture/mod-product-chain.md`；AGENTS / README / docs 索引 / CONTRIBUTING 链入；`plugin-sdk.md`（Python 时代、含动态加载与动作通道）加「已被取代」横幅 |
| **M2** schema 发现 | `ModFactory::settings_spec`（**静态**，未启用也能拿到）→ `GET /api/v1/mods` 带 `config` + `settings_spec`（secret 脱敏）+ `GET …/config`；Flutter 按 kind 渲表单 | `mod-system/factory.rs`、`mods_routes.rs`、`mods_api.dart`、`dev_tools_section.dart` |
| **M1** 持久化 | `enable` / `disable` / `config` **原子写回** `mods.json`（tmp + fdatasync + rename，复用 `plan_atomic_write`）；`mods_path_for_web()` | `mod_registry.rs`、`cli_entry.rs` |
| **M3** 模板 + 门禁 | `crates/live2d-ai-mod-template`（**不注册**进 `AVAILABLE_MOD_FACTORIES`，只作复制起点 + 活文档）；`start_one` 校验 `descriptor.api_version` vs `MOD_API_VERSION`，不兼容 → `Failed` 且 **factory.create 不被调用**（主链不崩） | `main.rs`、`mod_registry.rs` |
| **M4** 一等配置写回 | `ModServices.apply_settings`（namespaced JSON patch → 写盘 + `supervisor.reload()`）；未注入 host 时**默认拒绝**；删除旧的 `{"__apply_settings":true,…}` 事件走私 | `mod-system/services.rs`、`mod_registry.rs`、`local-llm` |
| （M4 附带） | `ModServices.settings`（**脱敏**读取：无密钥、无 `api_key_env` 变量名）+ `config_path`；`HostChannels.read_settings` | 同上 + `cli_entry.rs` |

**为什么 `apply_settings` 要一等化**：它过去藏在「事件 payload 里带一个魔法键」这条
走私路径上——主链的 `event_tx` 语义是「Mod→host 的日志/通知」，把**写配置**塞进
事件流，等于让「谁改了配置」无法从类型上看出来。现在它是一条有名字、有返回值、
有默认拒绝的能力。

## 3. `settings_spec` 发现闭环（M2）

- `GET /api/v1/mods` 每个条目新增 `config` 与 `settings_spec`（schema；旧 Mod 无则为 `null`）；
- **`secret=true` 的字段值永不出现在 GET**（`redacted_config`，按 schema 剥离）；
  另有 `GET /api/v1/mods/{id}/config` 单读（同样脱敏）；
- `settings_spec.fields[].kind` ∈ `bool / string / number / select`，前端统一渲染，**Mod 不得注入 HTML/JS**；
- Flutter `ModsSection`：有 spec 的 Mod 展开后按 kind 渲控件 + 「保存」
  （`POST /api/v1/mods/{id}/config`，显式 `Content-Type: application/json`），
  成败都有文案（失败带错误码）；无 spec 的旧 Mod 保持「一行 + 开关」；
  **secret 留空不提交该键**（不会把已存的密钥误清空）。

## 4. 角色卡标准 Mod（M5，主交付）

### 4.1 主链收敛（**破坏性**）

- `[persona]` 删除 `name / description / personality / scenario / first`，
  以及 `build_effective_system_prompt`（不再把名字/简介拼进 system）；
- `PersonaView` / `PersonaPatch` / resolve / egui 休眠壳同步收窄；
- Flutter 删除 `persona_card.dart`、`persona_import.dart` 与全部导入接线；
  「人设」分区只剩**系统提示词**（历史轮数移入开发者区）。

### 4.2 新 Mod `live2d-ai-mod-persona`（Rust，正式版候选）

- 解析 **SillyTavern V1 扁平 JSON / V2 嵌套 JSON / PNG 内嵌 `chara`**
  （`tEXt` 与未压缩 `iTXt`；压缩 `iTXt` 明确报错而不返回空卡）；
- 合成 `compose_system_prompt` = 卡字段 ⊕ **可选对话纪律模板**（Mod 内），
  经**一等** `apply_settings` 写回 `system_prompt`；
- **禁用即还原**：首次启用把主链原 `system_prompt` 快照到
  `persona-mod-base.txt`（与 `live2d-ai.toml` 同目录，已 gitignore），
  `shutdown` 写回——「禁用 Mod → 回到仅主链 system_prompt」；
- 可选 `say(first_mes)`（缺省关）；`settings_spec` 8 字段
  （路径 / JSON 文本 / 纪律模板开关 / 朗读开场白 / 四个手工覆盖）；
- 注册进 `AVAILABLE_MOD_FACTORIES`（3 → 4），`mod_count_is_three` → `mod_count_is_four`，
  id 断言同步。

### 4.3 升级迁移（**必须手改一次**）

`PersonaSettings` 带 `deny_unknown_fields`。老的 `live2d-ai.toml` 里若还有
卡字段，启动会**解析失败**（错误会指出具体键名）。删掉那几行，或用新的
`live2d-ai.toml.example`。人设改由 `persona` Mod 的 `card_path`（本机文件路径）
或 `card_json`（粘贴文本）提供；尚无浏览器内直接上传 PNG 的通道
（不为主链加 Mod 专用端点）。

## 5. Win 舞台背景图（M6，rc.3 §9.1 挂账）

rc.3 的现场是「Win 侧换背景图失败」，四个候选原因里三个可以在代码层钉死：

| 根因 | 修复 |
|---|---|
| **iframe 未就绪 / 重建时 `stage-bg` 被丢**（`sync` 不携带背景图，而背景图只在偏好变化时发一次） | `Live2DStage` 增 `stageImage` 字段；`_attach()` 每次挂桥**补发** `sendStageBg`，`didUpdateWidget` 独立处理图变化（不再被「底色没变就 return」跳过） |
| **localStorage 写失败静默吞掉**（`saveDisplayPrefs` 返回 `void`） | 返回 `bool`；写失败（无痕 / 存储被禁 / 配额满）在界面上给一句可执行文案，不再「显示已应用、刷新就没了」 |
| **选图读失败与「取消」不可区分** | `pickImageDataUrl` 返回三态（取消 / 成功 / 读失败），读失败如实说明原因 |

**未完成（须 Windows 侧做）**：在 Win 浏览器**选一张图 → 舞台可见变化 → 清图可还原**的
肉眼验收。本环境（WSL2）只能到：代码级根因修复 + Flutter 门禁 + 点火体检（见 §7）；
**不把「代码看起来对了」当成「Win 上验过了」**。
