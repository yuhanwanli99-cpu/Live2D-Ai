# v0.1.0-rc.2 — 第二基线：动作层删到底 + 模型闭环打通 + `.env` 成为密钥真源（2026-09-12）

> **版本线**：`0.1.0-rc.1` → `0.1.0-rc.2`（同一 RC 线的第二个基线，不是新功能版）。
> **范围真源**：[`docs/plans/PLAN-rc2-second-baseline-2026-09-12.md`](../plans/PLAN-rc2-second-baseline-2026-09-12.md) §0。

> **口径**：个人项目；可读性与工程优雅优先；弱化安全；**宁删勿加**；不做步骤 2（Mod 功能堆砌）。

## 1. 一句话

把「文本 → LLM 纯对话 → TTS → 口型 → Live2D 渲染 + Flutter UI」这条主路径
**做成唯一清晰、可阅读、可改动**的产品真相，并把挡住验收的工程债清干净：

- **动作层删到底**（不是「保留但没人调」，是**不存在**）；
- **模型库闭环打通**（单一模型根 + 激活即换皮，含导入入口）；
- **`.env` 成为唯一密钥真源**（前端可写 + 热重载——从此「改不了 key」不再是缺陷）。

## 3. 主路径如何变短

### 3.1 动作层：从「休眠」到「不存在」

rc.1 的裁决是「前后端整体拆除，core 子系统**刻意保留但休眠**」。rc.2 把「休眠」
**做成结构性事实**而不是承诺：

| 层级 | rc.1 | rc.2 |
|---|---|---|
| 动作驱动方 | director Mod（编译进去，manifest 控制启停） | **已删除**（归档 `archive/action-layer-p6`） |
| Mod → core 注入 | `HostChannels.trigger_action` → `supervisor.trigger_action` | **已删除**；`ModServices.action_tx` 仍存在（Mod API 契约）但注入的是固定休眠 sender（请求只留一行 debug 日志、返回 `false`） |
| supervisor 侧 | 空闲态 `action_rx` 分支会发 `RootEvent::Action` | **已删除** |
| capabilities | 广告 6 动作 / 3 来源 / 强度档 | **不广告**（schema v2） |
| 渲染面 | 350 行关键帧表 + 150 行测试，无人调用 | **已删除**（`surface.rs` 1721 → 1169 行） |
| core 子系统 | 保留 | **保留**（`#[doc(hidden)]`，归属声明 + 休眠台账） |
| **待机生命体征** | 保留 | **保留且未动一行**（`IdleState`/`idle_enabled`/`apply_idle_life`） |

护栏（防回归）：
`main.rs::mod_count_is_three`（工厂数不得回到 4）+
`mod_registry::tests::action_request_is_dormant_not_delivered`（动作请求必须**不被接受**）+
`dto.rs` 的「五个已删字段不得回来」断言。

### 3.2 模型库：从「两个根 + 找不到 model3」到「激活即换皮」

rc.1 的模型库有**两处硬缺陷**，且它们互相掩盖：

1. **模型双轨**：静态 `/models/*` 读 `<cwd>/assets/models/`，而 registry / import 写
   XDG `~/.local/share/live2d-ai/models/`。→ 即便前端补上 `sync.model`，被导入的模型
   也不会生效（iframe 永远拉 cwd）。
2. **`find_model3_json` 只扫顶层**，而仓库布局是 `assets/models/bai/runtime/bai.model3.json`
   （深一层）→ `import {"id":"bai"}` 必然回 400 **「连自家自带的模型都导入失败」**。

rc.2 的修法：

- **唯一模型根**：新增 `web_api/model_root.rs`，静态服务与 registry / import 共用它
  （`<cwd>/assets/models`，cwd 不在仓库根时向上找——与 `flutter_app` 同一口径）；
  registry 住模型根内部（`assets/models/model_registry.json`，已被 `.gitignore` 覆盖）；
  XDG 那条路径删除（本机从未存在，无内容可迁移）。
- **`find_model3_json` 向下看一层**（子目录排序保证确定性、不跟随符号链接）；
  连带修掉「登记相对路径时用 `id/ + file_name` 拼」造成的 `model_url` 404。
- **`app/status.active_model_id` 读真实 registry**：以前恒为 `"bai_001"`（registry 里
  根本不存在的字符串），所以「激活了但状态栏不变」是必然。现在 = registry 的
  `active_id`；没激活过时回落到**确实存在于磁盘的**内置默认模型，两者都不成立才报空。
- **热换契约落码**：activate 只登记 + 回**可 GET 的** `model_url`，**恒**
  `requires_restart=false`（渲染面本就支持热换——恒 `true` 会骗前端去提示「需重启」）。
- **前端接线**（这才是「换皮」真正发生的地方）：激活后 `sendSync(model: url)`，
  **等渲染面 `loaded` 回执**才说「已切换到 X」；拿不到回执就如实说「已登记，但渲染面
  未回执：舞台可能仍是上一个模型」。新增**导入入口**（`ModelsApi.import` 此前全仓
  **零调用方**，而空态却写着「然后在这里导入」）。

### 3.3 密钥：从「只能在后端进程环境里」到「`.env` 唯一真源 + 前端可写」

以前密钥**只存在于后端进程环境**（`ignite.sh` 用 `set -a; . ./.env` 导入，Rust 侧从不读
`.env`）。于是「界面上能改模型名、却改不了 key」——用户改完还是 401，且**无处可改**。

rc.2 的契约（用户口径）：

- 查找优先级写死：**`.env` 快照 > 进程环境 > 无（不鉴权）**；
- 读密钥**只能**走 `live2d_ai_runtime::secrets::lookup`（用 `std::env::var` 直接读会绕过
  `.env`）；实现是**进程内快照**，不用 `std::env::set_var`（Rust 2024 下是 `unsafe`
  且多线程不可靠）；
- `GET /api/v1/env` → 键名 + **是否已设置**（**永不回值**）；
- `PUT /api/v1/env` → 原子写 + `0600` + **就地改行**（保留手写注释，与
  `merge_into_toml` 同一条教训）+ 写后回读校验；加入 mutating 门禁；
- 写完刷新快照 + `supervisor.reload()`；`.env` 也纳入 `file_watcher`（外部手改同样即时生效）；
- 前端：LLM/TTS 两个分区里多了「保存密钥」一行（`obscureText`、保存后立刻清空明文、
  永不回显）。

### 4.1 那 3 跳为什么失败（**环境原因，不是 rc.2 的缺陷**）

本机 `[tts] base_url = http://127.0.0.1:8080/v1` **没有在跑**（`curl` 连不上），于是：

1. `TTS 有产物` FAIL、`口型有电平源` FAIL —— TTS 端点不可达，没有任何 audio 帧；
2. `LLM 有正文` FAIL —— **连带**结果：`text_delta` 帧在 v1 里由
   `GenerationFinished`（`ws/events.rs`）代理发出，而 TTS 错误是
   `fatal=true`，整轮直接判失败 → 那个锚点事件不来 → 文本帧不发。
   服务端 stdout 已证明**模型确实回了正文**。

⇒ 要让 `verify_core_chain.py` 全跳通过（以及 DoD 里的「能出声、口型动」），
先启动你自己的 TTS 端点（`live2d-ai.toml` 的 `[tts] base_url`）。

### 4.1.1 rc.2 内的补丁（2026-09-13）：推理模型的「思考」与输出上限

**现场**：用户报「清空历史后第一次、之后也有几次，对话没有模型返回」，且要求
「思考展开也加上」。

**查到根因（三步实测，不是猜）**：

1. **上游是推理模型**：直接打 `deepseek-flash` 的 SSE，每个 delta 除 `content`
   外还带 `reasoning_content`（一句「你好」就有 97 字思考）。而本项目的 SSE 解析
   **只读 `content`**（`llm.rs`）——思考被静默丢弃。
2. **思考与正文共用输出预算**：同一提问，`max_tokens=512` → `finish_reason=length`，
   正文只剩 **25 字**且以 `\sqrt{a` 收尾；`max_tokens=4096` → `stop`，正文完整 269 字。
3. **半句切不出完整句 → 一个字都不上屏**：正文上屏走的是
   「该句**语音已合成完毕**」（`SentenceVoiced`）→ `text_delta`（为的是文字与声音同拍）。
   被截断的正文没有句读结尾 ⇒ 装配器永远凑不出完整句 ⇒ **一条 `text_delta` 都不发**
   ⇒ 界面显示「本轮模型没有返回文字」。这就是「无模型返回」。

**修法（三处，都在 rc.2 内）**：

| 改动 | 位置 | 效果 |
|---|---|---|
| 解析思考并单列事件 | `llm.rs`（`LlmEvent::ReasoningDelta`，兼容 `reasoning` 别名）→ `EngineEvent::ReasoningDelta` → WS **新帧类型** `reasoning_delta` | 思考不再被丢；它**不进句子装配器、不进 TTS**（否则会把内心独白念出来） |
| 默认上限 512 → **4096** | `DEFAULT_MAX_TOKENS`；`live2d-ai.toml` 显式 `max_tokens = 4096`；`.example` 与前端文案同步 | 长思考不再把正文挤空 |
| 前端「思考」折叠区 | `ChatMessage.reasoning`（**不落盘**：思考比正文长 5–20 倍，写进 localStorage 会膨胀一个数量级）+ 气泡内的折叠区 + `settleTurn` 新增 `keepReasoningOnly` | 默认折叠（先看回复）；**只有思考、没有正文时默认展开**并说明「正文可能被输出上限截断、去哪调大」——不再把唯一内容折起来 |

**为什么新增帧类型而不是复用 `text_delta`**：`text_delta` 的语义是「与音频同拍的正文」，
会被追加到气泡正文；思考没有声音可对，混进去等于把模型的自言自语当回复显示
（旧前端尤其会这么做）。独立 type 让旧客户端自然忽略（`default: break`），是向后兼容的新增。

**追加（同日，用户报「TTS 自检没通但能正常出声」）**：这是又一个**假失败**。
实测三条：本机 CosyVoice 合成一次 2.4s 而自检默认只等 3s；链路正在合成时点自检
**稳定复现** `{"ok":false,"code":"timeout"}`，而同时刻语音完全正常；HTTP 循环是
**单线程**的，同步探针会把整个 API 占住它等待的全长（调到 15s 只会换成「界面卡 15 秒」）。
修法：自检改为**轻量连通探针** `GET {tts.base_url}/models`（毫秒级、不加载模型、
不抢上游），404 算可达（上游回话即通）+ `note` 说明；两处自检的密钥读取改走
`secrets::lookup`（原先直接读进程环境，非 `ignite.sh` 启动时会出同一类假失败）。
修后实测：空闲 **1–2 ms**；**链路正在合成时**三次全 `ok:true`（2 / 110 / 3 ms）。

**验证**：`cargo test`（新增 5+1+5 条后端/前端断言：思考不成句、帧类型独立、
折叠区行为、只有思考时的收口文案）；真机 `verify_core_chain.py` 用同一长思考提问
**18 跳全过**（含 3468 帧音频、11 句边界配对、`turn_status=completed`）。

  （`env!("CARGO_PKG_VERSION")`）→ `shell/flutter/pubspec.yaml` `0.1.0-rc.2+2`
  （`+2` 是 Flutter build number，与后端语义无关；前端不参与版本协商）。
- **顺序（冻结）**：**先本地提交 + tag** → Windows 点火通过（§4.2）→ 再
  `push origin main` + tag。**不许先推、后发现 `/app/` 还是 503**。
- **✅ 已按此顺序发布（2026-09-13）**：`65e62115..6ab4a074 main -> main` + `[new tag] v0.1.0-rc.2`。
  匿名 `git ls-remote` 核对：`refs/heads/main` = **`6ab4a074`**、`refs/tags/v0.1.0-rc.2` = **`82bd78c7`**
  （指向 `6ab4a074`）—— **代码、计划、交接、发布说明与 tag 都在远端**。
  本地 main 另有 1 个 **docs-only** 提交（记录本次推送本身 + 一处旧仓库名更正），
  因 token 已按建议即时销毁而未跟上；补推方式见交接 §9.2（不需要 token）。
  注：GitHub 仓库已改名 `Live2Dai` → **`Live2D-Ai`**（旧名会 302 重定向），本地 `origin` 已更正为规范地址。

## 7. 已知问题 / 留给 rc.3

| 项 | 说明 |
|---|---|
| **正文上屏依赖「该句语音合成完毕」** | 这是**刻意**的（文字与声音同拍，不让文字跑到声音前面）。代价：只要某一轮凑不出完整句——TTS 不可达、TTS 冷启动失败、或正文被 token 上限截断——**一个字都不会上屏**（用户看到「无模型返回」）。rc.2 已把**截断**这条主因修掉（见 §4.1.1）；「TTS 故障时也把已生成的正文交出去（并标明未收尾）」留 rc.3 决策——它要动上面那条同拍契约，需要单独论证 |
| `main.dart` God Object（1180 行） | rc.2 只做了**接线**，拆分是 rc.3 软目标 |
