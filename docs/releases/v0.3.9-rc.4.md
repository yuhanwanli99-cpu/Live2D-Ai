## 1. 设置模型去掉 vendor 快照（rc.1）

- `[llm].mode` / `[tts].mode` = `cloud | local` 就是**唯一**切换手段；二级字段仍住这两个表，
  仍走「保存并重载」。
- 删除 `[llm].vendor` / `[tts].vendor` 标签与 `[llm.vendors.*]` / `[tts.vendors.*]` 快照表：
  内置虚拟 `melo` 快照、`vendor_modified` 脏标记、一次 PATCH「快照→当前」复制全部移除。
- 本地 TTS 缺省仍由 `mode=local` 写入 Melo 那一组（`127.0.0.1:8091/v1` / 音色 `ZH` /
  `pcm` / 44100 / 单声道 / 无密钥），**不另做一份厂商表**。
- **旧 toml 仍能加载**：读入时忽略 `vendor` / `vendors`（不让 `deny_unknown_fields` 拦下启动，
  其它拼错键照旧报错）；**下一次保存不再写出这两键**，旧文件手写注释保留。
  夹具 `settings_tests_roundtrip::legacy_vendor_keys_are_ignored_on_load_and_dropped_on_save` 钉住
  「能加载 + 写回无 `vendor`/`vendors`」两件事。

## 4. 云端 TTS 点火不再等 `127.0.0.1:8091`（rc.1）

- `scripts/ignite.sh` 的就绪等待只认 `[tts].mode`：`local` 才等 `GET {tts}/models` = 200
  （最长 600 秒）；`cloud` **整段跳过**，页面就绪即打印地址并开浏览器。
- 理由：云端时核心只打 `[tts].base_url`，出声端点在云端；旧口径按 base_url 主机名判「是否本机」，
  把「云端地址填成本机 / 局域网代理」误判成要等一个永远不会起的 Melo。
- `mode=local` 仍由 `local-tts-melo` 按今天缺省拉起进程；本跳出声端点唯一权威仍是 `[tts]`。
