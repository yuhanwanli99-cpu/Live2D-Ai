## 0. 给导演讨论的结论

1. **「导演层」在同生态里是三种完全不同的东西，先分清再对照**：
   ① **决策层**（谁决定此刻该不该换情绪/动作）——分「主 LLM 内联标签」与「独立第二路 LLM」两派；
   ② **编排层**（会话/锁/能力探测/顺序执行）——只有 N.E.K.O. 的 `AvatarPerformance` 把它独立成模块；
   ③ **仲裁层**（哪个通道此刻能写参数）——VTube Studio 的 P0–P5 与 Cubism 的 PriorityNone/Idle/Normal/Force
   是长期工业惯例，且**不是 LLM**。
2. **N.E.K.O. 的 Live2D 路线 = 独立小模型给「角色回复」贴 5 情绪标签 + 回合收尾触发 + 映射表随机选表情**
   （`prompts_emotion.py:23`、`system_router/emotion.py:883`、`app-websocket.js:1511-1539`）。
   它**不分析用户输入**；分析用户的那条叫 `MasterEmotionTracker`，**明确不驱动皮套**
   （`main_logic/activity/master_emotion.py:29-35` 硬边界原文）。
3. **同类里的「第二路 LLM」已不是孤例**：my-neuro 的 `MotionDirector`、soullink 的
   `SoullinkLLMPlanner`、VT-Orchestrator 的 Motion micro-agent、Soul of Waifu 的决策 LLM、
   Amaidesu 的 Planner/Replyer 拆分，都是**独立于主对话的表演决策**。但它们**没有统一协议**，
   时间基准大多仍停在「句边界 / 墙上时钟 / 定时器」。
4. **成熟的只有仲裁层，不是决策层**。VTS 六级值提供者 + 平滑 fade、Cubism 四级 priority +
   表情独立 manager、Warudo 的 layer 互斥，是唯一经过产品验证的语义；
   「表演导演 = 独立一层」在工业界**尚无标准名字**——Warudo 的 Director 甚至是**相机导演**。
5. **本仓 T8 的口径在同类里没有反例，但有几处可以直接借用**：失败退回直送（本仓已有）≈
   my-neuro 的「8s 超时保留本地编舞」；只切分不改写 ≈ 无人做过（同类都在让 LLM **产出**台词或标签）；
   按句锚点与音频时钟（本仓 stage-clock）**比同类更严**。

## 1. N.E.K.O.（主案例）

### 1.1 一条链

```text
角色回复全文（回合收尾）
  └─ app-websocket.js finalizeAssistantTurn: 延时 100ms → analyzeEmotion(全文)
       └─ POST /api/emotion/analysis → 独立「emotion」模型档（温度 0.3，超时 30s）
            └─ {emotion ∈ 5 类, confidence} + 本地启发式覆写 + 低置信回 neutral
                 └─ window.applyEmotion → LanLan1.setEmotion(name)
                      └─ Live2D: emotionMapping{expressions, motions} → 随机取一个 + 50% 概率加播 motion
                      └─ 常驻表情层（跨轮保持）与 soft reset 独立于这一条
```

### 1.2 决策层：独立 LLM 打标签，输入是**角色回复**，触发在**回合收尾**

| 事实 | 证据 |
| --- | --- |
| 提示词只出 5 类（happy/sad/angry/surprised/neutral）+ confidence，附 8 条判定规则（防卖萌误判、防语气词误判） | `config/prompts/prompts_emotion.py:23-57`（`OUTWARD_EMOTION_ANALYSIS_PROMPT`） |
| 端点 `POST /api/emotion/analysis`，独立模型档 `aget_model_api_config('emotion')`，`temperature=0.3`、`timeout=30` | `main_routers/system_router/emotion.py:883-961` |
| 模型结果先过**本地启发式覆写**（≥4 分且置信 <0.8 才推翻模型；neutral 且置信 <0.6 用启发式补齐），置信 <0.2 强制 neutral | `emotion.py:1005-1029` |
| 触发点：一轮 AI 文本说完后的统一收尾（music → emotion → 字幕），主动消息分支也同样触发 | `static/app/app-websocket.js:1472-1483` |
| 前端 `setTimeout 100ms` → `analyzeEmotion(fullText)`，**5s 超时**，超时/失败只 warn，不阻断 | `app-websocket.js:1511-1539` |
| 送分析的文本 = **助手回复全文**（去掉 `[play_music:…]` 指令），不是用户输入 | `app-websocket.js:1487-1505` |

**旁路（用户侧）**：`MasterEmotionTracker` 每会话一个实例，异步喂用户自己的话，
出 valence/arousal 两维，喂 `FocusScorer`；文件头写明
*"This is NOT the OUTWARD_EMOTION_ANALYSIS pipeline that drives lanlan's avatar face…
This analyzes the user's own utterance and never touches the avatar channel."*
且有 TTL + 本轮回合新鲜度匹配，过期即 fail-open（`main_logic/activity/master_emotion.py:15-40,159-186`）。
→ **NEKO 把「用户情绪」与「皮套情绪」彻底切开**，与本仓口径相反（见 §4）。

### 1.3 渲染面（Live2D）：映射表 + 随机 + 常驻层

| 机制 | 行为 | 证据 |
| --- | --- | --- |
| 情绪→素材 | `emotionMapping.expressions[emotion]` 取候选，**随机选一个**；缺映射时按表情名前缀推导 | `static/live2d/live2d-emotion.js:1482-1497` |
| 动作 | 同一情绪且同一表情时，**50% 概率**只重播 motion | `live2d-emotion.js:1521-1526` |
| 互斥 | `isEmotionChanging` 期间新请求直接丢弃；受 `AvatarPerformance` 的 expression/motion 能力锁拦截 | `live2d-emotion.js:1453-1466` |
| 清理语义 | `clearEmotionEffects()` **只清 motion 参数，保留 expression**（"只清除motion参数，不清除expression"） | `live2d-emotion.js:1294,1413-1448` |
| 参数边界 | 表情记录初值时**跳过 `ParamAngleX/Y/Z` 与全部口型参数** | `live2d-emotion.js:44` |
| 常驻表情 | 独立一层 `applyPersistentExpressionsNative`：任何清除/重置后**立即重放**，并备份原值 | `live2d-emotion.js:212-215,1733-1805`；`docs/frontend/live2d.md`「`常驻` group 仅 expression」 |
| soft reset | 常量 `220ms / 200ms` 级别的软复位，避免硬跳变 | `live2d-emotion.js:10-13` |

**读法**：NEKO 的表情**设计上跨轮保持**，motion 到点即清——本仓是另一套语义：
双槽（`preset/mod.rs:26,107` `PresetSlot::Face`/`Gesture`）**按 `duration_ms` 到点整批撤销**，
`assets/actions/presets.json` 里 expression = 2600ms、motion = 900–1000ms
（该口径差已登记在 `docs/plans/RESEARCH-actions-director-audit-2026-09-21.md` §1.3/D8；
v1 契约新增 `hold=true 保持到下次指令 / false 按 ttl 回`，见 `performance-protocol-v1.md:84`）。

### 1.4 编排层：`AvatarPerformance`（同类里唯一的独立编排模块）

`static/avatar/avatar-performance-stage.js`（2,801 行）暴露 `AvatarPerformanceStage`（执行单个
sequence）与 `AvatarPerformance`（协调 session/能力/调用方）。合同逐条（`avatar-performance-stage.js:16-77`、
`docs/design/avatar-performance-module-maintenance.md`）：

- 版本化四件套：`avatar-performance-{stage,driver,coordinator,sequence}-v1`；
- **driver 方法表 22 个**（`isAvailable/resolveAvatar/capture/restore/acquireSession/applyFrame/hasMotion/
  playMotion/captureExpression/applyEmotion/resolveParamId/setParam/runPoseTimeline/lookAt/...`）；
- **sequence step 类型 15 种**（`frame/motion/motionWithFallback/optionalMotion/expression/emotion/param/
  poseTimeline/lookAt/clearExpression/clearParams/wait/sequence/speechCue`）；
- **capability 5 项**（`frame/motion/expression/params/lookAt`），driver 只实现子集，**缺失即安全 no-op**；
- 运行合同：**session 隔离**（旧 session 的延迟回调不得写新 session）、**能力锁释放必须幂等**、
  每步前复查 session、reduced-motion 时缩短但**仍做状态清理**、演出结束必须交还口型/视线/idle。
- 无 driver 时用 no-op driver/coordinator 兜底（`:79-118`），演出异常**不得**阻断聊天或模型加载。

→ 这一层与本仓「Mod 不得绕过 core 仲裁」「渲染面能力差异按 no-op」是**同构**的，
可当扩展多载体（VRM/MMD）时的对照清单；但注意其体量（2,801 行 JS）与维护成本。

### 1.5 第二条路线：VRM 的 `NekoMotionCore`（客户端确定性语义计划器）

**没有 LLM 参与**：`static/vrm/motion/semantics.json`（schemaVersion 3，`maxPlanItems: 3`）里是
「情绪 → 短语义短语 → 动作帧」的规则表 + 三套人格档案；`core.js` 做分句、短语匹配、
**否定/条件/过去时守卫**、歧义判定，然后路由到动作卡（`core.js:1440-1486,1715-1755`，
返回体里 `modelUsed: false`）。`runtime.js` 负责回合生命周期：

- 常量：`EMOTION_READY_WAIT_MS 900`、`TURN_END_GRACE_MS 240`、`BUFFER_SEAL_GRACE_MS 1200`、
  情绪证据 `DEBOUNCE 700ms`、情绪脉冲 `3000–7200ms`、情绪上下文窗口 `45s`（`runtime.js:9-40`）；
- 人格档 `classic_genki / tsundere_helper / elegant_butler` → `{energy, restraint, warmth}`（同上）；
- 情绪本体意图映射 `happy/excited/surprised/sad/cry/angry/shy/fearful/disgusted/tired`（同上）；
- **方括号舞台指示闭合即处理，正文留到回合结束**（"Closed stage directions are handled as soon as
  their bracket closes; visible prose is still meaningful and is analyzed at turn end"，`runtime.js:566-570`）；
- 与 idle / 点唱机争所有权：`window.__nekoMotionOwnsVrmPlayback` 外部 hold 先占位，失败要交还（`runtime.js:1-6`）；
- 只通过生命周期桥收 `turn-start / turn-end / emotion-ready / speech-cancel`（`runtime.js:1081-1092`）。

**为什么值得看**：这是「**同一条回复，两套时间语义**」的实例——舞台指示（作者写死的动作）走即时，
散文（模型自由发挥的部分）走回合收尾；并且它把「情绪分析还没回来」显式建模成等待 900ms。
本仓 T8 的 `segments`（按句切分 + 头/颈/表情）可以直接对照这张表校准自己的 at/hold 常量。

### 1.6 旁支两个，不要和动作导演混为一谈

- **idle 恢复合同**：Live2D 待机动作存在 `_reserved.avatar.live2d.idle_animation`，
  恢复前要校验 load token/模型身份，循环/结束回调必须能力检测，清表情/预览后统一回单一恢复入口
  （`docs/live2d_motion_plan.md`）。本仓对应物是 `IdleState` 呼吸/眨眼/微表情——**两者都属「没有台词时谁拥有皮套」**。
- **教程导演 `static/tutorial/yui-guide/director/`**（10 个文件、13,656 行，其中 `director-core.js` 3,606 行）：
  它是**脚本化业务流程编排**（页面流转 + 语音队列 + 演出），`emotion-bridge.js` 只是把 Live2D
  表情应用串行化。**名字叫 director，职责与动作导演无关**——引用时务必区分。

### 1.7 N.E.K.O. 的已知代价（引用时不要只抄优点）

- 情绪到得晚：回合收尾后才分析，**情绪与当轮语音不同拍**；前端 5s 超时会**整条丢弃**。
- 随机成分重：候选随机 + 50% 概率重播 motion + 点击效果抢占（`setEmotion` 要先清点击效果 ID，
  `:1470-1473`），是「老虎机感」的现成来源。
- 一套回复两条语义并存（Live2D 表情跨轮保持 vs 本仓式自动撤），是它自己文档都承认的口径差。
- 跨端重复实现：Live2D / VRM / MMD / PNGTuber 各有一套 emotion 通道（`docs/frontend/{live2d,vrm,mmd,pngtuber}.md`）。

### D 组：本仓既有调研里已核实过的调度/待机惯例（不重复抓取）

- **Shimeji**：条件门 + 整数权重轮盘赌（顶层）、硬优先级 `Select`（行为内）、**粘性自环 100:1:1**；
  **无冷却机制**（需自行补）。
- **soullink `IdleActionScheduler`**：最近窗口去重（默认 3）+ 方向反重复 + **幂律间隔采样**
  （`min 4.8s / max 11.5s`）+ 幅度多因子连乘 ±14% 随机；`focusLevel` 是贯穿全局的注意力旋钮。
- **权重必须按动作时长归一化**（Streck & Wolbers 2018 摘要原话），否则短动作在视觉上消失。
- **Ukagaka**：引擎只给时钟 + 输入事件，`Reference4` = 距上次用户操作秒数，策略全在脚本侧；
  说话通道被占时 `Reference3=0` 降级为 NOTIFY。
- **oneko**：确定性升级阶梯 + **睡眠状态由用户活动唤醒**（把随机性外包给用户行为）。
- **Convai gaze**：优先级分层 + 层内粘性 + **非对称迟滞**（晋升 1.0s / 释放 5.0s）+ **所有权锁**。
- 以上全部出处与数值见 `docs/research/idle-motion-tracking-and-director-2026-09.md` §6、§7。

## 4. 可借鉴 / 明确不抄

**可借鉴（都能落成小改动）**

1. **能力与所有权合同**（N.E.K.O. `AvatarPerformance`）：driver 能力声明 + 缺失 no-op + session 隔离 +
   锁释放幂等 + 结束交还口型/视线/idle。本仓渲染面已有能力差异处理，缺的是**显式声明面**。
2. **跨轮保持 vs 到点撤销必须二选一并写死**（N.E.K.O. 的表情跨轮保持 + 本仓 2.6s 自动撤并存，
   已被 `RESEARCH-actions-director-audit-2026-09-21.md` §1.3 记成「老表情」的一半来源）。
   工业参照：Warudo 的「同层互斥 + 退出时长」是最小可用的声明式写法。
3. **低置信兜底**：NEKO 的启发式覆写（高分且模型置信不足才推翻）+ 置信 <0.2 回 neutral，
   是「模型给了但不可信」的廉价处置范式；本仓二路 LLM 目前是「坏 JSON 整个回退」，粒度更粗。
4. **超时不等于失败**：my-neuro 8s 超时后保留本地编舞、本仓退回直送、soullink 无 Planner 时
   只显示即时情绪——三种写法都指向「表演可以没有，台词不能没有」。
5. **空闲/待机调度**（§2 D 组）：粘性自环、去重窗口、幂律间隔、时长归一化、注意力标量，
   可直接喂养本仓 `IdleState` 与将来的随机 idle；**先做时长归一化**再谈随机。
6. **「舞台指示即时、散文收尾」的双时间语义**（N.E.K.O. VRM）：若将来支持标记/旁白，
   这是一条已经被产品验证过的切分方式。

**明确不抄**

1. **把情绪/动作标签写进主 LLM 的可见输出**（A 组全部）：与本仓「上屏 == 送 TTS == 原文逐字不变」
   正面冲突，且要额外做标签剥离。
2. **用角色回复驱动皮套**（N.E.K.O. 与多数同类）：维护者 2026-09-21 口径是**用户输入**。
   2026-10-07 只开了一条窄口：问句（`？` / `?`）可以补一次歪头和思考表情，见
   `docs/plans/PROMPT-director-expression-2026-10-07.md`。整篇五类情绪、随机选表情、表情跨轮常驻，仍然不抄。
3. **随机重播 + 点击效果互抢**（N.E.K.O. `setEmotion`）：老虎机感的现成来源。
4. **为情绪判断再打一次独立大模型**（NEKO 的 5s 超时档）：本仓 T8 已裁「复用主 LLM」，
   省一次网络与一个密钥面；若将来要独立小模型，先算清「多一次往返 vs 情绪准一点」的账。
5. **把导演和相机导演混名**（Warudo 的 Director）：文档措辞上要避免歧义。
