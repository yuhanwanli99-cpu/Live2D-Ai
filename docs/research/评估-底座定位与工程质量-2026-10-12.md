## 1. 代码里真正闭环的底座（关掉全部可选 Mod 后仍能独立转完）

真源：`docs/architecture/core-chain-baseline.md`、`README.zh-CN.md` 开头。

```
文本 → LLM（OpenAI 兼容 /chat/completions，请求体无 tools）
     → 按句读切句（引擎给句界）
     → TTS 整句合成（OpenAI 兼容 /audio/speech，PCM）
     → WS 下发 PCM 分片（带 sentence_seq / start / end / volume / muted）
     → 前端封 WAV → <audio> 播放
     → 服务端音量包络按 audio.currentTime 写 ParamMouthOpenY
     → /render（wasm，wgpu/WebGPU→WebGL）皮套渲染
```

| 层 | 主人 | 守住的事实 | 真源 |
| --- | --- | --- | --- |
| 回合 | `live2d-ai-core` reducer | epoch / 生成闩锁 / 播放闩锁；停一次隔绝上一代迟到事件 | `crates/live2d-ai-core/` |
| 说话 | `live2d-ai-runtime` `ConversationEngine` | 一句一个 TTS 任务；思考不进 TTS；失败轮 `text_fallback` 补正文上屏 | `conversation/engine.rs` |
| 出声 | `[tts]` + 前端媒体元素 | 端点只来自配置；本地 TTS Mod 只拉起进程、不改地址 | `tts-is-core.md` |
| 嘴 | wasm `mouth` 输入 | 预设表与导演 cue 的测试**禁止**写 `ParamMouthOpenY` | `l2d-wasm-demo/src/mouth.rs` |
| 皮套 | `l2d` + `l2d-wasm-demo` | 模型 / 物理 / 待机呼吸眨眼；待机与动作是两套机制 | `pose_stack.rs` |
| 壳 | Flutter `/app/` | 聊天 / 设置 / 舞台；无第二套原生窗口 | `shell/flutter/` |

`AVAILABLE_MOD_FACTORIES` 现行 **6 个**：`external-input` / `persona` / `voice-input` / `memory` /
`director` / `local-tts-melo`。**无桌宠、无壁纸**。缺省启用只有外部分发注入与 Melo 进程拉起；
主链不依赖任何 Mod 才能说话、对口型、把皮套画出来。

## 2. 表演还没进底座（本轮最重要的工程判断）

用户把「表演 / 嘴型 / TTS」放在同一层。**嘴型和 TTS 已是底座；表演还在底座旁边，且有三个家，没有一个坐在 reducer 里。**

1. `live2d-ai-core` 的 `action/` 与 `performance/` **仍在编译**，`lib.rs` 不变量 4/6 仍以它们为前提；
   产品路径上**没有驱动方**，`ModServices.action_tx` 固定返回 `false`
   （`mod_registry.rs` 的 `action_request_is_dormant_not_delivered` 守着）。
2. 现行真会让皮套点头/微笑的是**旁路**：`director` 按用户输入出 `action_cue`，
   或默认关闭的 `[performance]` 第二路 LLM 出 `body/head/expression`。
   渲染面 `PresetRuntime` 写参数，时间基准 = 音频播放时钟；**口型不走这条路**。
3. 导演关掉并重载后，句子照样流式进 TTS、口型照样动，只是没有表情与头颈 cue。

**另一个未裁完的产品分叉**：底座若是「皮套表演这句台词」，cue 该跟**角色正在说的内容**走；
现行规则层打分的是**用户刚说的话**，角色回复只在问号上补一次歪头和思考脸。两套语义共用同一条 cue 管道。
`performance-protocol-v1.md` §1 自己把「谁拥有说话权」标成未裁决（Q1）。
