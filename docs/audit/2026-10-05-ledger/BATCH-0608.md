## 四个可核点
1. **⇒⇒⇒⇒⇒⇒ 头注讲得最好的是「文件名的来历」这一段** ——
   它把「原名 `actions_section.dart`」→ **为什么从来就不是动作分区** →
   **哪次裁决让动作子系统移出成品** → **改名以名实相符** 讲全了
   ⇒⇒ **⇒⇒⇒⇒⇒⇒⇒⇒ 判据：改名这件事，头注要讲「原名 + 为什么会误叫 + 哪次裁决 + 改成什么」。
   本仓这段是范本**（与 B0500「一条禁令要带后果」同族：禁令带上了它的历史后果）。
2. **⇒⇒⇒⇒⇒⇒ `:3-4` 说「三组」，`:49` 只挂 1 个 part** ⇒⇒
   **⇒⇒⇒⇒⇒⇒⇒⇒⇒ 三组里只有「舞台背景图」被拆走（成了 background part）**，
   **另外两组（舞台与口型 / 互动）仍在宿主里** ⇒⇒
   **⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒ 709 行的构成是：三组里两组 + 一个 part 的挂载点 + import 段。**
3. **⇒⇒⇒⇒⇒⇒ 「原文件四个域」的说法要收窄** ⇒⇒ B0607b 的 `appearance_background.dart:5`
   写「`appearance_section.dart` 一度把『外观 / 舞台单图轮播 / 舞台与口型 / …』四个域
   全装在一个文件里（**1489 行**）」⇒⇒ **⇒⇒⇒⇒⇒⇒⇒⇒⇒ 那是**拆分前**的状态**；
   今天的宿主是 709 行、挂 1 个 part ⇒⇒
   **⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒ 判据：读「这个文件是怎么来的」的头注时，
   要把「拆分前的数字」和「当前数字」分开记** ——
   否则会把 1489 当成现状（B0440 第 8 形态：`grep -c` 计的是行不是次，
   这里同类：**头注里的数字是历史值**）。
4. **⇒⇒⇒⇒⇒⇒ 一处与 B0607b 的结论对上了**：宿主头注**确实没写「拆完还剩多少」**
   —— 它讲了文件名来历（14 行）、讲了规格（4 行），**没讲 part 拆分的来龙去脉**
   ⇒⇒ **⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒ 而 part 那个文件的头注讲了**（B0607b 记的 `:3-10`）
   ⇒⇒ **⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒ 判据（修正我上一批的说法）**：
   **「拆文件的头注要写拆完剩多少」—— 本仓不是「没写」，是写在 part 那一侧、
   宿主那一侧只讲别的事** ⇒⇒ **⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒ 撤回上一批那条「可疑处」**，
