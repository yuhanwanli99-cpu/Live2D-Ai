## B0635 · EmphasizedText 的规则（emphasized_text.dart:1-21）
```
:1  /// **轻量强调文本**：把 `**这样**` 渲染成粗体，而不是把两个星[号露出来]
:5  /// 这个项目的说明文案一直是按 Markdown 习惯写的
:7  /// 那些字符串进了 `Text`——**`Text` 不认 Markdown**
:11 /// 两种修法：把 15 处 `**` 从文案里删掉（**丢强调**），或者**真的渲染**；
:12 /// 选了后者——这些句子里被强调的正是**用户最容易误解的那[一处]**
:18 /// - 成对的 `**…**` → 粗体；
:19 /// - **落单的 `**` 原样保留**（**不猜、不吞、不抛**）——文案写错[时]
:21 /// - 空强调（`****`）不产生空 span。
```

三个可核点：
1. 规则三条，第 2 条是**兜底**（「不猜、不吞、不抛」）
   ⇒ 与 B0453「缺字段不回落成一个有意义的值」同族：解析不了时不猜
2. `:11-12` 把**两种修法与选择理由**都写下来了（「删掉 = 丢强调」/「选了后者，
   因为被强调的正是用户最容易误解的那一处」）
   ⇒ 与 B0500「一条禁令要带后果」同族
3. 第 3 条「空强调（`****`）不产生空 span」是一个**具体的边界**
   ⇒ 与 B0443「一个 switch 覆盖 n 种情况 + `_ => fallback`」同一类
   （把「奇怪输入」列出来，而不是让它们落到未定义行为）

**可提炼**：一个解析器把「落单怎么办」写清楚、而调用它的地方却不检查自己是否满足前提
⇒ **规则的兜底会掩盖调用方的疏忽** ⇒ 与 B0488「head-file 白名单扫描」同一类（**防御在错的一侧**）
