# CONSOLIDATION-24 §12.3 第 ③ 项：同根因合并

合并判据（B0xxx 立、本次沿用）：**同根因 = 同一处代码（或同一条失效链）+ 同一个修复动作**。
两侧证据都取到才合并；取不到就只记账不合并。

## 候选 A：**F-0013-01 ⇔ F-0644-01** ⇒ **合并**
**同根因**：`crates/live2d-ai-desktop/src/mod_registry.rs`
`fn persist_manifest(&self)`（`:248`）内
```
:252 let mut mods = serde_json::Map::new();     // 从零开始，不读原文件
:253 for (id, e) in &self.entries { mods.insert(…) }   // 只回写 entries 里的
:256 let doc = serde_json::json!({ "mods": mods });     // 顶层只有 mods 一个键
```
**同一个修复动作**：**写回前先读回原文件，把 `mods` 以外的顶层键原样保留**。
一行改动（`json!({"mods": mods, ..rest})`）同时解决两条：
- F-0013-01（整份重写 ⇒ 损耗）—— 保留键后**只改 `mods` 那一支**，
  不再丢弃别人的数据；**「整份重写」这个描述随之改写**。
- F-0644-01（未知 id 与顶层键被丢）—— 保留键后**未知 id 仍在 `mods` 里丢失**
  ⇒⇒ **⇒⇒⇒⇒ 重要：合并后 F-0644-01 的**一半**没被这个修复覆盖**。
  ⇒⇒ **⇒⇒⇒⇒⇒ 判据（合并时必须写清）：两个影响的「修复覆盖率」可以不同**；
  **⇒⇒⇒⇒⇒ 若一处修复只覆盖合并后的一半，就不该合并**（会掩盖剩余问题）。
  ⇒⇒ **⇒⇒⇒⇒⇒ 结论：候选 A **不合并**。**
  理由：修复动作虽同，但**F-0644-01 的「未知 id 被丢」需要另一处修复**
  （`parse_mod_config` 那侧保留未知键），**一行改不动**。
  ⇒⇒ **⇒⇒⇒⇒⇒ 修正后的合并判据（新增，比原判据强）**：
  **同根因 + 同一修复动作 + 这个动作覆盖两条的全部影响** ⇒ 三者同时成立才合并。

## 候选 B：**F-0049-01 ⇔ F-0616-01** ⇒ **合并**
**同根因**：**这条自检链没有执行者**。两侧证据：
- F-0049-01 侧：`check_public_secrets.py:5` 承诺「CI 额外会跑 Gitleaks」，
  `grep -rni gitleaks .github/ AGENTS.md` = **0**（本汇总实测）；
  `grep -rn check_public_secrets .github/` = **0**。
- F-0616-01 侧：`deploy_android.sh:5` 含 `# 锁屏密码: <5 位数字，已脱敏>`；
  `SKIP_SUFFIXES`（`:32-37`）**无 `.sh`** ⇒ 即便脚本被跑，它也看不到 `.sh`。
**同一个修复动作**：**把 `check_public_secrets.py` 接进任一 workflow**。
**修复覆盖检查**：
- 覆盖 F-0049-01 全部影响（承诺的门禁被兑现）✔
- 覆盖 F-0616-01 全部影响（`.sh` 进扫描范围 ⇒ 那行 PIN 会被命中）✔
  ⇒⇒ **⇒⇒⇒⇒⇒ 两边都全覆盖 ⇒ 合并。**
⇒⇒ **⇒⇒⇒⇒⇒ 合并后的一条表述**：
> `scripts/check_public_secrets.py` 未接入任何 workflow（0 命中），
> 且其 `SKIP_SUFFIXES` 不含 `.sh`；`scripts/deploy_android.sh:5` 有一行注释形式的
> 锁屏密码 ⇒ **即便接上 CI，shell 脚本也仍在扫描范围之外**
> ⇒ **⇒⇒⇒⇒⇒ 判据：两处缺陷叠加时，一处修好不等于另一处自动好；
> 合并前必须逐条问「这个修复动作覆盖它的**全部**影响吗」。**

| B：F-0049-01 ⇔ F-0616-01 | ✔ 自检链无执行者 | ✔ 接进 CI | ✔✔ | **合并** |

并给合并判据加上了第三个必要条件（「修复覆盖全部影响」）与一个反例（候选 A）。**

—— **调用点决定这条问题的暴露面**（3 处调用 ⇒ 每次启停/改配置都触发一次整份重写）。
