```rust
/// 默认最大缓冲字符数：**安全阀**，不是切句目标。
/// **2026-09-10 契约调整（用户裁决：一句一单元，延迟可接受、断句不可接受）**。
/// **旧值 `48` 会把超过 48 字的长句按字符位置硬切**，TTS 侧表现为一句…   // :57-60
if self.buf.chars().count() > self.max_chars {
  // **安全阀**……正常路径**绝不**走到这里……
  // 本分支只在「流式输入已超过 `max_chars` 却仍无任何[句读]」时触发——
  // 例如**模型吐出一大段没有标点的文字**。
  // 触发时**优先在弱标点处断开**（听感是自然停顿）……
  // **确实一个弱标点都没有才退回按字符位置硬切**。**这样即使安全阀也不会把一句话从中间劈成两半。**
  let limit = self.byte_of_char(self.max_chars);
  let cut = self.last_soft_break_at_or_before(limit).unwrap_or(limit);        // :133
```

四个可核点：
1. ⭐⭐⭐⭐ **安全阀是三层降级，每一层都比上一层「更不愿意」切**：
   | 层 | 切点 | 切出来的东西 | 用户会不会觉得坏 |
   |---|---|---|---|
   | 正常 | **真实句读** `.?!。！？…\n` | 一句一单元 | 不 |
   | 降级① | **弱标点** `，、；：…` | **自然停顿** | 不 |
   | 降级② | **字符位置硬切** | 一句话被劈开 | ⭐ **会** ⇒ 所以是**最后一层** |
   ⇒⇒⇒⭐ **⇒ 判据是「这一层切出来的东西，用户会不会觉得是坏的」**
   ⇒⇒⇒⇒ **⇒ 而硬切的条件被写成「**确实一个弱标点都没有**」** —— 一个极窄的例外
2. ⭐⭐⭐ **「正常路径**绝不**走到这里」被明说** ⇒⇒ **⇒ 安全阀的标准写法：先说它不该被走到**
   ⇒⇒ **同 B0407 核的「200 条在约 6 秒内被灌满」的写法**（都在说「这条路径本不该命中」）
3. ⭐⭐⭐ **触发条件被写成「**模型吐出一大段没有标点的文字**」** ⇒⇒ **⇒ 一个具体的上游行为**
   ⇒⇒⇒ **⇒ 安全阀防的是「**模型不配合**」，不是「文件坏了」**
4. ⭐⭐⭐ **旧值 `48` 的后果被逐字写下**（**把超过 48 字的长句按字符位置硬切** · **TTS 侧表现为一句…**）
   ⇒⇒ **⇒ 一次调参事故** ⇒⇒⇒ **⇒ 它解释了为什么这个数从「切句目标」改名为「安全阀」**

⇒ ⇒⭐⭐⭐⭐ **而本批把 B0412 的根因说完了、并**改变了 F-0411-01 的性质**：
> **Dart 侧只有「句界」一档，而这一侧有三档**（句界 / 停顿点 / 硬切）
> ⇒⇒ **⇒ 而三档的排序判据是「切出来的东西用户会不会觉得是坏的」**
> ⇒⇒⇒⭐⭐ **⇒ 这也解释了为什么 `；` 在 Rust 侧不是句界**：它是**降级①**的切点，
> **而 Dart 侧把「降级①的点」当成了正常档** ⇒⇒⇒⇒⇒ **⇒ 两边不是「集合不同」，是「档位不同」**
⇒ ⇒⇒ **⇒ 而修法也随之更准**：
**不是把 `；` 拉进 runtime 那一档；而是让 Dart 侧明确「我只有句界这一档」**，
**或补上「停顿点」那一档、但显式写明它**不**构成「立即播报」的理由**
