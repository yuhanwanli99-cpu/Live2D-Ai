## ③ 同根因归并：**「台账漂移」正式立为模式 J**

| F-0042-01 | `ActionSource::LlmTool` 字段注：「主 LLM 的 tool action 输出」 | 该产出路径 rc.2 已拆；这一档现在由 host 承接 **Mod 动作请求** | **台账口径描述的是已拆除的子系统** |

⇒ **模式 J：台账与代码演进不同步。** 本仓的台账（AGENTS.md 休眠台账、模块头注、字段注）
写得极其详尽，但它们**没有跟着代码一起被更新**。三个样本的共同点是：
**台账描述的是「当时的决策」，代码执行的是「后来的现实」，而澄清后者的话只存在于另一处
（变更日志注释 / 另一个模块的字段注）**。
**危害不是「文档错了」而是「不可核」** —— 审计者/维护者按台账去核，
要么 grep 不到锚点、要么 grep 到相反的结论（F-0040-01② 就会让人以为动作驱动方还在册且可能被接回）。
⇒ 与模式 D 的区别：D 是**注释与相邻代码**脱节；J 是**台账与跨文件/跨版本的代码演进**脱节，
且**澄清句存在于别处**——这使它更难自查，因为自查者通常只读台账或只读代码的一侧。

**候选模式 J'（休眠代码自身是否仍正确）**：B0042/B0043 连着两批证明，
台账只回答了「**谁不调用它**」，没有回答「**留下的那些代码自身是否仍然正确**」。
本轮恰好给出了正面答案（口型所有权与红线 O 同向、参数所有权用「释放」而非「写零」、
`envelope` 的不变式由私有性结构保护），但这是**运气**，不是台账要求的。
