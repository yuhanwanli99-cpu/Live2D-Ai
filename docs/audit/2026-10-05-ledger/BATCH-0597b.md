## 三处命中
```
:168 // （[kBubbleReadingWidth]）：面板再宽，一段话也不该横着…
:174 maxWidth: kBubbleReadingWidth,     <- 用在 LayoutBuilder 里
:295 const double kBubbleReadingWidth = 480;
```

## 三个可核点
1. **⇒⇒⇒⇒ ⇒⇒⇒⇒ ⇒ `:295` 是一个裸的 `const double = 480`，没有 `///` 说明**
   ⇒⇒ **⇒⇒⇒⇒ ⇒⇒⇒⇒ ⇒ 与 `breakpoints.dart` 的对比**：
   那边 `SizeClass` 的每个成员都有 `///`（区间 + 行为后果），
   这边这个**布局上限只有一个数字** ⇒⇒
   **⇒⇒⇒⇒ ⇒⇒⇒⇒ ⇒ 判据：命名常量的文档要求与枚举成员不同**——
   枚举成员是**选项**（读的人要判断选哪个），常量是**事实**（读的人只需知道它是多少）
   ⇒⇒ **⇒⇒⇒⇒ ⇒⇒ 两者都要文档，理由不同**；**但 480 这个数字有上游理由**（阅读上限）
   却**只写在调用点 `:168` 而不是定义点 `:295`** ⇒⇒
   **⇒⇒⇒⇒ ⇒⇒⇒⇒ ⇒ 判据：理由写在定义处，调用处只写用法。**
2. **⇒⇒⇒⇒ ⇒⇒⇒⇒ ⇒ 两道约束的关系是「与」**：`LayoutBuilder` 给容器宽
   （面板实际多宽）∧ `kBubbleReadingWidth`（480 上限）⇒⇒
   **⇒⇒⇒⇒ ⇒⇒⇒⇒ ⇒ 判据：当一个值同时受「容器」与「上限」两处约束时，
   写代码的人要清楚**最终取谁** ⇒⇒ 本处是 `min(容器, 480)` 的形状
   ⇒⇒ **⇒⇒⇒⇒ ⇒⇒⇒ ⇒ 未核**：`:174` 那行到底是 `min(...)` 还是直接 `kBubbleReadingWidth`。
3. **⇒⇒⇒⇒ ⇒⇒⇒⇒ ⇒ 480 与 B0596b 提到的「expanded 下聊天面板 340 px」构成一对**：
   面板 **340** < 上限 **480** ⇒⇒ **⇒⇒⇒⇒ ⇒⇒⇒⇒ ⇒ expanded 这一档下
   **第二道约束是空转的**（永远由面板宽决定）⇒⇒
   **⇒⇒⇒⇒ ⇒⇒⇒⇒ ⇒ 判据（新增）：**上限类常量要问「它在各档下真的生效吗」** ——
   340 < 480 ⇒ medium 档要看面板多宽才知道，**本批未核 medium 的面板宽**。

## 未核
