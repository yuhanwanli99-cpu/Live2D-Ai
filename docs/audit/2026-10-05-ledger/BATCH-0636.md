1. **⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ 两份**逐字相同**，而 `appearanceSectionSource` 的定义只有 3 行**

   **B0635 那张「8 / 2 / 1」表里的「2」，经核是「2 份**完全相同**」** ⇒⇒ ⇒⇒ ⇒
   **⇒⇒⇒⇒ ⇒⇒ ⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ 修正后的表述**：
   **重复的「份数」要分两问：① 有几个文件各写一份 ② 那些份**内容一样吗****
   ⇒⇒ ⇒⇒ ⇒ **⇒⇒⇒⇒ ⇒⇒ ⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒⇒ ⇒ 第一问问不出来
   ⇒⇒ 就不能说「这是重复」** ⇒⇒ ⇒⇒ ⇒
   **⇒⇒⇒⇒ ⇒⇒ ⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒⇒ 本批之前 B0633b 核 `stripCommentsAndStrings` 时
   是**两问一起做的**（先数份数、再算 md5）⇒⇒
   **⇒⇒⇒⇒ ⇒⇒ ⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒⇒ 判据（把两问写成固定顺序）：
   **⇒⇒⇒⇒ ⇒⇒ ⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒⇒ 「**先问几处、再问是否相同**」——
   否则会把「同一个函数写在两个文件里」与「同一逻辑的两个实现」混为一谈**
2. **⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ 而这个函数读的是**两个文件拼接**
   （`appearance_section.dart` + `appearance_background.dart`）
   ⇒⇒ **⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒⇒ ⇒⇒ 承接 B0600c / B0601b 核的结论**：
   `appearance_background.dart` 是 `appearance_section.dart` 的 **`part`**
   （`appearance_section.dart:49 part 'appearance_background.dart';`）
   ⇒⇒ ⇒⇒ ⇒ **⇒⇒⇒⇒ ⇒⇒ ⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒⇒ 所以「拼接两文件」在**语义上等于**
   「读一个 Dart 库的全部源码」**（`part` 与宿主同属一个库）⇒⇒ ⇒⇒ ⇒
   **⇒⇒⇒⇒ ⇒⇒ ⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒⇒ 判据（可复用）：
   **当一个「拼接多个文件」的工具存在时，要在头注里说明**为什么是这几个**
   —— 本仓没写，而「为什么是这两个」正是 B0600c 核过的关键（它们是一个库）**
   ⇒⇒ ⇒⇒ ⇒ **⇒⇒⇒⇒ ⇒⇒ ⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒⇒ ⇒ 建议（P3，不立）：

   ⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒⇒
   **本批我自己犯了一次范围错**：用
   `awk '/^String appearanceSectionSource/,/^}$/'` 取函数体 ⇒⇒
   **该函数是箭头函数、以 `;` 结尾而非 `}` ⇒ 范围没有停 ⇒ 匹配到了整个文件**
   ⇒⇒ 因此我先得到的两个 md5（`be3dbed5` / `b4f69f6a`）**与函数无关**，
   我据此写的「两份不同」**是错的** ⇒⇒ 改用 `sed -n '16,19p'` 后确认**逐字相同**
   ⇒⇒ ⇒⇒ ⇒ **⇒⇒⇒⇒ ⇒⇒ ⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒⇒ ⇒ 判据（可复用，B0440 第 6 形态的又一次）：
   **`awk` 的 `start,end` 范围遇到「结尾形态不符合预期」的函数会一路吞到文件尾** ——
   箭头函数以 `;` 收尾、区间函数以 `}` 收尾 ⇒⇒
   **⇒⇒⇒⇒ ⇒⇒ ⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒⇒ ⇒ 核函数体一致性时，
   优先用「取固定行数 + 眼看一遍」而不是「按行尾自动截」**
   ⇒⇒ ⇒⇒ ⇒ **⇒⇒⇒⇒ ⇒⇒ ⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒⇒ ⇒ 代价记录**：本批若不复核，
   ledger 里会留下一条「两份不同」的错误结论，且它**看起来合理**
   ⇒⇒ ⇒⇒ ⇒ **⇒⇒⇒⇒ ⇒⇒ ⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒⇒ 承 B0587 那次
