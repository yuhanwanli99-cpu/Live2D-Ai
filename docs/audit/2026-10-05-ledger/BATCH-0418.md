## ★ 本批产出：**B0417 那条观察落地**（0 条新发现）
> 「**# 被修掉的是什么**：四个「一次性结果」挂在 `MainApp` 的 State 上：
> `_llmTest` / `_ttsTest` / `_adminMessage` / `_stageImageMessage`……
> 它们过去**只在下一次同类操作时**才被覆盖，**切分区不重置**。于是：用户测出「**失败：401**」
> → 修好配置 → 切走 → 切回 **那句失效的结论还在**，而它描述的已经是**上一套配置**了。」      // :4-12
> 「**还有一层更细的**：连点「测试连接」之后**立刻切走**，响应几秒后才回来 ⇒ 那条结果会
> **落在用户已经离开的分区上**，**看起来像是刚测的**。」                                  // :14-16
> 「**# 为什么这里用源码扫描而不是 widget 测试**：`MainApp` 的 State 是私有的，而它依赖 `http`
> 客户端做真实请求；**为了这一条断言去搭一套 HTTP 打桩，成本远大于收益**，还会把测试绑死在…」 // :18-22
```
五个可核点：
1. ⭐⭐⭐⭐⭐ **「被修掉的是什么」被写成一条用户走过的具体路径**：
   「测出『**失败：401**』→ 修好配置 → 切走 → 切回 ⇒ **那句失效的结论还在**，
   而它描述的**已经是上一套配置**了」
   ⇒⇒⇒⭐ **⇒ 这是一个可复现的脚本**，不是「结果可能不新鲜」这样的形容
   ⇒⇒⇒ **⇒ 同 B0328「两层必须同时变」的写法：给一个**看得见的中间态****
2. ⭐⭐⭐⭐ **而它点名了「**还有一层更细的**」**（连点后立刻切走 ⇒ **结果落在用户已离开的分区**、
   **看起来像是刚测的**）⇒⇒⭐ **⇒ 两个层次分列、且不把第二个当第一个的注脚**
   ⇒⇒ **⇒ 「还有一层」这个措辞把「不是全部」说清了**
3. ⭐⭐⭐⭐⭐ **「为什么用源码扫描而不是 widget 测试」单独立节**，理由**三条 + 代价两个半句**：
   ① State **私有** ② 依赖**真实 HTTP** ③ ⭐ **「成本远大于收益」**（**一条判据**）
   ④ ⭐⭐⭐ **「还会把测试绑死在…」**（**将来会疼**）
   ⇒⇒⇒⭐⭐ **⇒ 两者不同**：**③ 管当下（现在不值得）· ④ 管将来（这个选择会让测试变脆）**
4. ⭐⭐⭐ **而 `_adminMessage` 的改名理由**：「**旧名字会让人误以为它属于那条已删除的链路**」
   ⇒⇒ **⇒ 与 B0393 核的「留这段是因为下一个人很可能再按旧名误判一次」是**同一类理由**
   ⇒⇒⇒⭐ **⇒ 而 B0393 我以为是个例，现在看是**本仓第三次**：`actions_section` 文件名 ·
   `_actionMessage` 字段名 · 本条**测试手段的选择** ⇒⇒⇒⭐⭐ **⇒ 三次都是「防一个看似合理的误判」**
5. ⭐⭐ **而字段名被逐个列出**（`_llmTest`/`_ttsTest`/`_adminMessage`/`_stageImageMessage`）
   ⇒⇒ **⇒ 这就是 B0417 说的「被逐字扫的那些字段」** ⇒⇒⇒ **⇒ 上一批的观察落地了**

⇒ ⇒⭐⭐⭐⭐ **可提炼**：
> **「为什么用这种测试手段」应当单独立节，并写出它的**代价**——而不只是它的理由。**
> ⇒⇒ **「成本远大于收益」是一条判据**（同 B0395/B0398 的「不引入不可测的代码」同一族）**
> ⇒⇒⇒⭐⭐ **⇒ 而「还会把测试绑死在 X 上」是代价的另一半**：
> **它说的是「将来会疼」** ⇒⇒⇒⇒ **⇒ 一条判据管当下、一条管将来**
