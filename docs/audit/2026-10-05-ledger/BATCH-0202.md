```

**引用侧枚举：声明 ↔ 引用双向对账**

台账**不得含有「其实已经被引用」的过期条目**（**只减不增**）          ← 台账**自洁**且**方向写明**
台账里的名字**都真的存在**（防**改名 / 删档后台账变成陈旧清单**）     ← 台账防**自身陈旧**
ThemeExtension 结构枚举（防「**加了字段忘了 copyWith / lerp**」）   ← Flutter 最经典的那个坑

```

### ⭐ 正面模式 **P21（新）**
> **当「登记/声明」与「引用」两处并存时，为它们建一个双向台账，并给台账本身加三条约束：
> ① 台账里的名字**必须真实存在**（防改名/删档后台账变陈旧）
> ② 台账**不得含「其实已被引用」的条目**（**只减不增**）
> ③ **未被引用的必须显式登记**（不许沉默）**
> 再加上**成对互异 / 唯一性 / 下限**等约束 ⇒ **把设计系统的「品味规则」变成可执行断言。**
