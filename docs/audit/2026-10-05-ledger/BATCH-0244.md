## 本批产出：**0 条新发现**；⭐ 立**正面模式 P28**
> 「命令通道与运行态**共用 runtime 锁**：Mod 未启用时 host 回 **503 command_unavailable**。
> 所以停用时导入按钮是**禁用**的（**而不是让用户点一下才吃一个错误**），并**就地说明原因**；
> 导入成功后**不必**再启停一次——人设已经…」                      // :36-38
四个可核点：
1. ⭐ **约束被点名到机制层**：「命令通道与运行态**共用 runtime 锁**」⇒ ⇒ 导入失败是**运行时锁**，**不是 UI 的选择**
2. ⭐⭐ **被否掉的替代方案被写出来**：「**而不是让用户点一下才吃一个错误**」⇒ ⇒ **P22 + P1** 同款
3. ⭐ **替代做法给了**：「并**就地说明原因**」⇒ ⇒ 禁用的控件**在它被禁用的地方**解释了自己
4. ⭐ **顺带去掉一步冗余操作**：「导入成功后**不必**再启停一次」⇒ ⇒ 说明还告诉用户**不需要做什么**

⇒ ⭐ **正面模式 P28（新）**：**把「不可用」做成「禁用 + 就地说明」，而不是「可点 + 吃错误」。**
⇒ 因为后者把**契约限制**（runtime 锁）伪装成**用户失误** ⇒ 用户会以为自己操作错了
⇒ 与 B0227「**不假装成功**」同族：那管「假装成功」，这条管「**假装可用**」
