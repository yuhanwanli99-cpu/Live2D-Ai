## ⭐ 本审计的核心资产：**九条正面模式**（与具体仓库无关，可直接带走）

前面 156 批里，**缺陷侧的收获（P1–P3 的 9 条）远少于**这些 —— 因为一个被反复治理到
四次事故全部留下编号与复审的代码库，**它的好做法比它的缺陷更值得记录**。
以下每条都**有 1–6 个实测样本**（括号内为本审计的核验位置）。

### P1 · 理由的写法：**每个非平凡决策都配一句「不这么做的话，用户会看到什么」**
不是「请妥善处理」，而是**可观察的后果**。
- `background_hydration.rs:172-173`「整份重写会把这些抹掉——**用户不会立刻发现，等发现时已经找不到原来的注释了**」
- `app_shell.dart:664`「**界面在骗人**」→ 删掉会骗人的说明文字
- `secrets.rs:202`「没有 ```` ` `chara` 块」类错误文案都带**用户能照做的下一步**

### P2 · **私有汇合 + 策略闭包**：用「唯一实现 + 末端策略闭包」表达「多入口行为必须一致」
在**类型层面**排除漂移，而不是靠测试保证。
- `secrets::lookup`（**6 个消费者**，含 Mod 侧复用）· `asset::assemble`（磁盘/内存两入口）·
  `_applyPrefs`（偏好生效唯一漏斗）· `confirmLeave`（三处拦截共用一入口）

### P3 · **更严的写法要连「更松的写法在哪里」一起写进注释**
下一个维护者最容易写的正是那个更松的版本，而**他不会想到它踩的是哪条红线**。
- `field_map.rs:148-149`「不能只判 `scale_class == Expression`（**那会把 `ParamMouthOpenY` / `ParamBreath` 放进来**）」
- `normalize_resource_ref` 遇 `..` **拒绝**而非折叠（归一逻辑若错就放行）· `guess_format` **先查长度**再索引
- 最强一档：**把「关掉某能力」建模为「不存在该能力」**（`DisabledStaging` 没有 HTTP 字段）

### P4 · 竞态要用**对抗性评审的编号**记录，并在「**权威落闩**」之前关闭
- `turn.rs:443-447`「复审 P0-2 场景 B」：20ms tick 观察与同步判定的竞态；
  并说明**为何事后补 `Cleared` 无法纠正**已落闩的 outcome ⇒ 与 core「双闩锁恰一次」对上

### P5 · **部分投递必须放回 / 补齐，不得静默截断**（4 例）
- 空音频块**带双边界标记**（`worker.rs:113-117`）· 残余事件**排空补处理**（`turn.rs:327-344`）·
  句界**由引擎给**，不用 epoch 推断（`broadcaster.rs`）· **部分入环的 PCM 尾段放回下一轮**（`turn.rs:377-384`）

### P6 · 每个 spawn 的 future / 每条打开的通道，**都必须被驱动到确定的终态**（3 例）
- `worker.await`「**无条件 join，杜绝泄漏**」· `gen_fut`「**绝不 abandon（D2 契约）**」· 残余事件排空而非丢弃

### P7 · **每个「会做 X」的断言都配一个「不会做 X」的对照**（否则「永远做 X」也能过）
- `拒绝坏值` + **`接受合法值`** · `坏档要备份` + **`缺档不备份`** ·
  路径守卫 `合法 id` + **四类反例**（空·点 / `..` / 分隔符 / 特殊字符）
⇒ **这正是 B0001/B0002 两处假绿所缺的东西** —— 那两处**不是「没有测试」，
而是「测试缺对照面」**，所以断言可以恒真。

### P8 · **测试要显式隔离自己的前提；前提不成立时跳过，而不是硬断言**
- `token_check_precedes_gate:199-101`「若进程环境已有该 token，会**压过** config 里配的 ⇒ 前提不成立 ⇒ `return` 跳过」
⇒ 跳过的**判据与被测规则同源**；用**运行期**跳过而非 `#[ignore]`（干扰条件是**环境相关**的）

### P9 · **降级在本层静默，在上一层类型化 + 计数**（4 例）
本层可返裸 `None`/`false`，但**信号必须被上一级接住**：稳定原因码 + 计数器 + 可见状态。
- `client.rs` `None` + `FallbackReason` + `PerformanceStats`（B0151）·
  director `DisabledStaging` + `degraded_note`（B0106）·
  `drain_residual_events` 丢弃 / 排空并警告（B0134）·
  `verify_core_chain` 探针不可用 ⇒ job **skipped 而非 passed**（B0053）
⇒ **与 F-0048/F-0049/F-0050 方向相反**：那三条是**信号没有出口**（CI 不调扫描器 · 不构建产物 · 探针读错文件）。
⇒ **分界线：信号有没有被上一级接住。**
