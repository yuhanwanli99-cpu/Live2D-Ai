## ★ 本批产出：**分工的理由是两个情况**（0 条新发现）
```dart
// :178-188   status = "weird_state"（**有值，但客户端不认识**）
'{"mods":[{"id":"x","name":"X","status":"weird_state"}]}'
expect(m.statusLabel, **'weird_state'**);      // :186 原样透出
expect(m.isRunning, **isFalse**);               // :187 ⭐ 而「是不是运行中」也被断言
// :189-197   status **缺字段**（没有这个键）
test('**status 为空** → 「未知」', … '{"mods":[{"id":"x"}]}')
expect((await api.list()).single.statusLabel, **'未知'**);
```
四个可核点：
1. ⭐⭐⭐⭐⭐ **而这两个不是「两种风格」，是**两个不同的情况**：
   | 测试 | 情况 | 结果 | 方向 |
   |---|---|---|---|
   | `:186` | **有一个我们不认识的 status**（服务端**变了**） | **原样透出** | ⭐ **让变化**看得见** |
   | `:189` | **status 缺字段**（**根本没有值**） | **「未知」** | ⭐ **说得清** |
   ⇒⇒⇒⭐⭐⭐ **⇒⇒ 而两者的处理方向恰好相反** ⇒⇒⇒⭐⭐⭐⭐
   **⇒⇒⇒ ⇒ 「变了」要**看得见**（透出）· 「缺了」要**说得清**（「未知」）**
2. ⭐⭐⭐⭐ **而 `:187` 连 `isRunning` 也断言为 `false`** ⇒⇒⭐⭐
   **⇒⇒ 未知态 ⇒ **不是「运行中」** ⇒⇒⇒⭐ **⇒ 而「原样透出」是测试**故意要求**的**：
   **它要让「服务端给了一个我们不认识的字」这件事在测试里可见**
3. ⭐⭐⭐⭐⭐ **而这修正了我对 B0426 那条注释的读法**（它看起来矛盾、其实不矛盾）：
   > B0426 注释说：「**只认一个 ⇒ 坏 Mod 会在界面上露出裸英文 `failed`，「出错」提示永远不出现**」
   ⇒⇒⇒⭐⭐⭐ **⇒⇒ 那条说的是「**已知的坏值**不该露英文」（用户看到的是 bug）**
   ⇒⇒⇒⭐⭐ **⇒⇒ 而这里说的是「**未知的值**就该露原样」（开发者看到的是变化）**
   ⇒⇒⇒⭐⭐⭐⭐ **⇒⇒⇒ ⇒⇒⇒ 两者的判据是「**谁在看**」**
4. ⭐⭐⭐⭐ **⇒ 而这个判据是可迁移的**：
   > **「未知值该透出还是该映射」取决于读者** ——
   > **给用户 ⇒ 映射成可读的话**（且**映射本身要有测试钉住**）·
   > **给开发者 ⇒ 原样透出**（**让变化可见**）
   ⇒⇒⇒⭐⭐ **⇒ 而本仓两边都做了、且各自有测试** ⇒⇒⇒⭐⭐⭐ **⇒ 这比我 B0426 记的「两个都认」更完整**
