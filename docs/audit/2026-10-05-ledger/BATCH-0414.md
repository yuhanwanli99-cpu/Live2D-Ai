## ★ 本批产出：**B0413 留的数值与它的理由**（0 条新发现）
> 「旧值 `48` 会把超过 48 字的长句**按字符位置硬切**，TTS 侧表现为一句被[拆成]多个请求
> ⇒ **每个请求各有一段合成延迟** ⇒ **播放时逐段空档**，听感即『…』」                       // :60-62
> 「现在默认 **200**：**正常口语句长（中文约 10–40 字）永远碰不到这个上限**，
> 因此**一句话恰好对应一次 TTS 请求**。只有在模型吐出无标点长文时才[触发]」              // :63-66
> `pub const DEFAULT_MAX_CHARS: usize = **200**;`                                     // :67
> 「创建切句器。`max_chars` 为缓冲上限，**会被钳制到 ≥1**。」`max_chars: max_chars.max(1),`  // :69-73
```
四个可核点：
1. ⭐⭐⭐⭐ **旧值的失败被追到用户可感知的形态**（四步因果链）：
   **一句被拆成多个请求 ⇒ 每个请求各有一段合成延迟 ⇒ 播放时逐段空档 ⇒ 听感即「…」**
   ⇒⇒ **同 B0329「两个理由都不是性能」的写法：结论落到可感知的形态**
2. ⭐⭐⭐⭐ **而新值的理由是**两个比值**：「**正常口语句长（中文约 10–40 字）永远碰不到 200**」
   ⇒⇒ **200 ÷ 40 ≈ 5 倍余量** ⇒⇒⇒ **由此得出的结论是契约级的**：
   「因此**一句话恰好对应一次 TTS 请求**」
   ⇒⇒⇒⭐⭐ **⇒ 「一句一单元」那条红线在**参数层**的落地是一个比值** ⇒⇒⇒ **⇒ 而它是被算出来的**
3. ⭐⭐⭐⭐⭐ **而 `max_chars: max_chars.max(1)`** ⇒⇒ **⇒ 这正是 B0407 那条
   「`assert(capacity > 0)` 在 release 下失效」的**正确做法** ——
   **不是断言、是一个 clamp** ⇒⇒⇒ **且注释把 clamp 写在签名下面**（不是只写在 assert 上）
   ⇒⇒⇒⇒⭐⭐ **⇒ 同一关注、两种语言、两种可靠性**：
   **Dart 侧用 `assert` · Rust 侧用 `max(1)` ⇒ 而只有后者是可靠的**
   ⇒⇒⇒⇒⇒ **⇒ 这给了 Dart 侧一个具体可抄的改法**（若那条 P3 级观察被采纳）
4. ⭐⭐ **而 `200` 与 B0395 核的 `kStageImageMaxChars = 1500000` 是不同量纲的数**
   ⇒⇒ **⇒ 而两者都被放在各自文件的「预算」注释下** ⇒⇒⇒ **⇒ 「预算」在本仓是个**类别**、不只 5 MB 那一条**
