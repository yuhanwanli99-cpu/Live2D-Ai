## 四个可核点
1. **⭐⭐⭐⭐⭐ ⇒⇒⇒⇒ `:7` 的注释「豁免面（**越小越难被侵蚀**）」**
   ⇒⇒ **⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒⇒ ⇒⇒ 判据（本批最值钱）：
   **豁免规则要写「为什么不给它更大的范围」** ——
   豁免面每扩一个文件，下一个人扩它的**心理成本就低一分**
   ⇒⇒ ⇒⇒ ⇒ **⇒⇒⇒⇒ ⇒⇒ ⇒⇒⇒⇒ ⇒⇒⇒⇒ ⇒ 判据（可提炼）：
   **写豁免时附一句「这个豁免要守住的性质」**（本例：越小越难被侵蚀）
   ⇒⇒ ⇒⇒ ⇒ ⇒⇒ **⇒⇒⇒⇒ ⇒⇒ ⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒ 与 B0628 核的 `kNotYetWired`
   「显式登记，防止新加的死令牌混不进来」**同族** ——
   ⇒⇒ ⇒⇒ ⇒ **两处都在管同一件事：让「例外」不能悄悄长大。**
2. **⭐⭐⭐⭐⭐ ⇒⇒⇒⇒ `:16-22` 给协议时长豁免的理由是**语义不同**，不是「实现不同」**
   ⇒⇒ **⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒⇒ ⇒⇒ 判据（承 B0629 第 ④ 点的「写我没做 X 要带前提」）：
   **豁免理由要落在「这个东西本质上不是那一类」** ——
   原文把四类时长（WS 分片 20 ms / 重连退避 / 渲染面桥 ≤30 Hz 节流 /
   IndexedDB 挂死兜底 3 s）**逐个列名**再下结论
   ⇒⇒ ⇒⇒ ⇒ **⇒⇒⇒⇒ ⇒⇒ ⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒ 判据（可复用）：
   **举 3–4 个具体实例再下结论，比一句「它们不是 UI 动效」有说服力**
   ⇒⇒ ⇒⇒ ⇒ ⇒⇒ **⇒⇒⇒⇒ ⇒⇒ ⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒ 承 B0618 核的
   「抽象地说『会花屏』不如给出『各按 t 与 1-t 淡入淡出』」**同一取向**
3. **⭐⭐⭐⭐⭐ ⇒⇒⇒⇒ 而 `:20-22` 还记录了**豁免面扩大的一次历史**：
   「`lib/data/` 是 **2026-09-27 加进来的**（背景字节库）…归到 `AppDurations`
   会让『4 档动效』这个…**背上它完全无关的语义**」⇒⇒
   **⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒⇒ ⇒⇒ 判据（承 B0604b / B0601 的历史注释族）：
   **每次扩大豁免面，要写「谁被加进来了、它为什么不属于这一类」** ⇒⇒ ⇒⇒ ⇒
   **⇒⇒⇒⇒ ⇒⇒ ⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒ 与 B0628 核的台账履历**同族** ——
   ⇒⇒ ⇒⇒ ⇒ **两处都是「把『为什么现在是这样』写成一段可读的履历」** ⇒⇒ ⇒⇒ ⇒
   **⇒⇒⇒⇒ ⇒⇒ ⇒⇒⇒⇒ ⇒ 正面模式 P44（新）：
   **豁免面 / 台账这类「例外集合」的注释里应有一段「加过什么、为什么」**。
4. **⭐⭐⭐⭐⭐ ⇒⇒⇒⇒ 而 `:29` 明写下一条规则是「**逐个点名**的时长豁免文件（**不是整个目录**）」**
   ⇒⇒ **⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒⇒ ⇒⇒ 判据（与第 ① 点配套，本批第二个可提炼的）：
   **目录级豁免要配一条文件级豁免** ⇒⇒ ⇒⇒ ⇒
   **⇒⇒⇒⇒ ⇒⇒ ⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒ 为什么**：「一个目录里的文件会增删」
   ⇒⇒ ⇒⇒ ⇒ **⇒⇒⇒⇒ ⇒⇒ ⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒⇒ 目录豁免是给「一类东西」的，
   文件豁免是给「一个具体错」的** ⇒⇒ ⇒⇒ ⇒
   **⇒⇒⇒⇒ ⇒⇒ ⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒ 与 B0621 核的
   「收窄『唯一』的适用范围」**同族** —— 都是**先给宽的、再给窄的**，
   而不是只留一种粒度 ⇒⇒ ⇒⇒ ⇒
   **⇒⇒⇒⇒ ⇒⇒ ⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒ 判据：
   **豁免机制最好同时提供「粗粒度（省事）」与「细粒度（精确）」两档**，
   并让细粒度那档在注释里被点名。**
   ⇒⇒ 顺带：`design_tokens_lint_test.dart:5` **`import` 另一个测试文件**
   （`show stripCommentsAndStrings`）⇒⇒ **⇒⇒⇒⇒ ⇒⇒ ⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒ 判据（细节）：
   **两个测试共用一个工具函数时，那个函数不该住在其中之一**
   —— 现在它住在 `design_tokens_test.dart` 里、被 lint 测试反向 import
   ⇒⇒ ⇒⇒ ⇒ **⇒⇒⇒⇒ ⇒⇒ ⇒⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒⇒⇒ ⇒⇒ 后果是：改那个文件会同时影响两个测试，
   而文件名不提示这一点** ⇒ **P3 候选，不立**。
