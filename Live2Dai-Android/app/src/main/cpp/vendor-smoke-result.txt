--- 分析结论 ---
① TU 级隔离 = 生产真实模式：flat_consumer（平铺域）与 framework_consumer+FIX（包裹域）
   各自独立编译 PASS；extern "C" 同名符号保证链接层兼容。
② 根因（framework_consumer 无 FIX 失败）：官方 Live2DCubismCore.hpp 把 PurismCore.h 整体包进
   namespace Live2D::Cubism::Core；PurismCore.h 内部 #include <stdint.h>/<cstdint> 因此在命名空间内
   展开，libc++ 的 stddef/nullptr_t 声明落入命名空间 → 全局作用域缺失 ::nullptr_t →
   后续任何 C++ 标准头（<new>/<string>/<cstddef>）报 'no member named nullptr_t in the global namespace'。
③ 最小解法（已实证，无需改 purism/ 或上游；M1 在 CMake 实施）：编译 framework 源码时
   target_compile_options 加 -include stddef.h -include stdint.h（全局先行包含系统头，
   guard 使包裹内的再次包含成为空操作）。framework_consumer + FIX → PASS（仅 1 个上游无害
   -Wreorder-ctor 警告：CubismModel.hpp 初始化列表顺序，非本工程问题）。
④ include guard 遮蔽：同一 TU 先包裹包含后，平铺再包含 PurismCore.h 被 guard 静默跳过，
   平铺域符号（::csmVersion/csmGetVersion）不可见。生产无需同一 TU 双作用域：TU 级隔离即可。
⑤ 双作用域强制混编（#undef guard 后）→ C 链接声明冲突：包裹域 csmMoc/csmModel 与平铺域为
   不同类型，同名 C 链接函数（csmReviveMocInPlace/csmGetSizeofModel/csmInitializeModelInPlace/
   csmUpdateModel 等）报 'functions that differ only in their return type' / 'conflicting types'。
   → 同一 TU 内不可同时使用两个作用域的 Core API（M1 设计约束，无需 patch）。
